## 근거와 구현 범위

- 기관별 쿼리·HTTP 상태·항목별 근거는 `docs/qa/LINER_SEARCH_EVALUATION_2026-11-18.md`, API 계약·기본 모드·30건 방침은 `docs/tech/LINER_API.md`를 읽는다.
- 검색 결과 관찰 키는 requestId/results/totalCount이고 결과에는 title/url/description/hostname/faviconUrl/date가 있었다. description은 검색 스니펫이며 생성 답변·별도 인용문이 아니다.
- 공식 문서에서 Router/Chat Completions API와 `POST https://platform.liner.com/api/v1/chat/completions`를 확인했다. 모델을 실제 호출하거나 계정 권한·생성 품질을 검증하지 않았다. 규칙·Search 근거·템플릿 기본 경로는 유지한다.
- 현재 research의 모드 선택과 README·환경 예시·AGENTS 실행 문단을 맞췄다. 판정 엔진·화면·딜러 순위·메일 발송은 구현하지 않았다.
- 30건은 캐시 없는 기본 최대 60요청, 동시 2요청·요청당 8초 제한·점진 처리다. #29에서 재시도를 넣으면 Retry-After를 지키고 요청당 1회로 제한해 최대 120시도 상한을 둔다. 현재 research 자체에는 자동 재시도가 없다. 캐시는 기관·국가·질의·추출 버전·언어/국가 옵션 등을 키로 삼고 모드·출처·시각을 남긴다.

## 검증

- npm ci·lint·typecheck·build가 통과했다. 자동 테스트 20개가 통과했으며 모두 주입 응답을 사용해 외부 API 호출과 비용이 없다.
- 모드 미설정·빈 값·auto와 키 존재 조합, 명시 sample, 잘못된 모드, HTTP 라우트의 키만 설정한 실행을 모의 호출로 검증했다. 오류 본문·키가 브라우저 응답에 노출되지 않는 회귀 테스트도 유지했다.
- 라이브 평가는 개발PM이 별도로 수행했다. 실제 모델 호출·메일 발송·브라우저 E2E·계정 실제 정산액 확인은 미실행이다.
- 수동 3/5 결과를 자동 판정 정확도로 보고하지 않는다. 질의별 지연 1.8~3.9초는 이번 표본이며 30건 즉시 완료를 보장하지 않는다.
- 비밀값·실제 수신 주소·인증 헤더·잔액 본문은 문서나 로그에 남기지 않았다.
