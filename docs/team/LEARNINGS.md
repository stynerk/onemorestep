# 시행착오 기록

이 프로젝트에서 틀렸거나 되돌린 일을 기록한다. 세션을 시작할 때 전체를 읽는다. 다른 프로젝트에도 해당하는 일은 hq `LEARNINGS.md`에 적는다.

2026-11-16에 공통 항목 네 개(Our Adventure 병목, 갱신할 수 없는 곳에 둔 문서, 봇 멘션 ID 착각, 같은 작업 폴더 사용)를 hq `LEARNINGS.md`로 옮겼다.

형식: 날짜, 무슨 일이 있었나, 원인, 다음부터 이렇게 한다.

## 2026-11-12 개발 세팅: 프레임워크가 역할 문서를 자동 수정했다

- 무슨 일: Next.js 16.4.6 개발 서버가 AGENTS.md에 프레임워크 안내 블록을 자동 추가했다. 생성된 블록만 제거했다.
- 원인: 개발 서버의 agentRules 기본 동작을 시작 전에 확인하지 못했다.
- 다음부터: 기존 팀 규칙이 있는 저장소는 next.config.ts에서 agentRules=false로 자동 생성을 끄고, 서버 실행 후 문서 diff도 검사한다.

## 2026-11-12 Windows 검증: 한글 파이프 입력이 검사 결과를 왜곡했다

- 무슨 일: HTTP 응답은 정상이었지만 PowerShell에서 Node로 전달한 한글 비교 문자열이 변환돼 검사가 실패했다. Unicode 이스케이프로 다시 검사해 통과했다.
- 원인: 셸 파이프 문자 인코딩과 HTTP 본문 인코딩을 구분하지 않았다.
- 다음부터: 한글이 포함된 검증은 UTF-8 파일이나 Unicode 이스케이프를 사용하고 실패 원인을 앱과 검사 도구로 나눠 확인한다.
- #74 보충: Windows PowerShell에서 실행할 테스트용 .ps1의 한글은 UTF-8 BOM이나 Unicode 이스케이프로 보존한다. 격리 사본의 파트너명만 ASCII로 바꾸고 검사를 다시 실행했다.

## 2026-11-12 동시 병합: 닫힌 PR 브랜치에 문서 커밋을 추가했다

- 무슨 일: PR #5가 다른 세션에서 병합되는 동안 추가 문서 커밋을 기존 브랜치에 올렸다. 이후 최신 main에 필요한 내용만 대조 반영했다.
- 원인: 원격 PR 조회와 푸시 사이에 상태가 바뀌었다.
- 다음부터: 병합 직전 원격 상태를 재확인하고, 이미 병합된 경우 최신 main의 변경을 보존해 후속 문서를 정리한다. 같은 체크아웃에서 동시에 커밋하지 않는다.

## 2026-11-18 외부 호출 차단 테스트의 예외가 처리됐다

- 무슨 일: #26에서 외부 호출을 막았는지 확인하는 모의 fetch가 예외를 던졌고, 호출부는 이를 예시 응답으로 처리했다. 예시 응답만 확인하면 호출이 시도돼도 통과할 수 있었다.
- 수정: 호출 횟수를 직접 기록해 각 오프라인 모드에서 0회인지 확인한다.

## 2026-11-21 라벨링 화면에 기관 실재 여부가 빠졌다

- 라벨링 화면에서 기관이 실재하는지 알 수 없어 평가 70건 중 가상 기관 11건에 유효·애매가 붙었다.
- 원본 정답을 보존하고 정정 파일을 별도로 추가했다. 기록된 검색 응답을 재생해 동일한 예측을 두 정답에 대조했다.
- 다음 평가에서는 라벨링 화면에 기관 실재 여부를 표시하고, 집계 전에 무효 판정과 넘길 곳 없음 기준을 확인한다.

## 2026-11-21 예약 도메인 분기가 등록 기관의 재검토를 막았다

- 실시간 시연의 첫 후보에서 등록 기관의 이름은 검색됐지만 공식 URL은 없었다. 예약 이메일 분기가 애매였던 건을 무효로 바꿨다.
- 예약 이메일 무효 처리를 미등록 기관에 한정했다. 등록 기관은 기존 사칭 검사와 공식 근거 부족 분기를 유지한다. 두 상황을 회귀 테스트에 넣었다.
- 평가 정답과 대조하기 전에 저장 및 실시간 시연의 판정과 넘길 곳을 함께 확인한다.

## 2026-11-21 기관 실재 단서와 이메일 소속 단서를 분리한다

- PR #66에서 미등록 기관이라는 이유로 예약 이메일을 무효 처리해 실재 기관명을 사칭한 문의까지 버렸다.
- 이메일과 독립된 공개 출처에서 실재 기관의 이름·유형·소재지·사이트 표기를 대조하고, 예약·닮은꼴 이메일은 사칭 의심으로 권역팀에 표시한다. 같은 약어가 나온 용어집·소프트웨어는 기관 근거로 잡지 않는 회귀 검사를 추가했다.
- 정식 기관명과 제목이 일치하고 호스트에 약어와 고유 이름이 붙어 있는 경우도 있다. 합친 이름이 호스트 구성 요소와 일치할 때 기관 근거로 채택하고 약어만 같은 경우를 회귀 검증했다.

## 2026-11-21 소재지와 연락처 단서의 경계를 확인한다

- #72 검토 중 이메일 도메인 일부가 일치하거나 과거 시설의 주소가 검색 결과에 있어도 현재 소속이나 소재지로 읽을 수 있는 조건을 발견했다.
- 다른 도메인의 연락처는 기관 자체 사이트, 연락처 필드와 도메인 전체를 대조한다. 새 주소·시설 단서는 제목이나 본문에서 부정·과거·예정으로 설명하면 사용하지 않는다. 오프라인 170건 재생과 별도로 이 입력을 회귀 테스트에 넣었다.
