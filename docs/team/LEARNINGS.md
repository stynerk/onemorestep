# 시행착오 기록

틀렸거나 되돌린 일을 기록한다. 세션을 시작할 때 전체를 읽는다. PM이 구글 드라이브 팀 로그 시트의 T_시행착오 탭과 맞춘다.

형식: 날짜, 무슨 일이 있었나, 원인, 다음부터 이렇게 한다.

## 2026-11-10 Our Adventure: HJ가 병목이 됐다

- 무슨 일: 에이전트화를 진행하다 승인 대기가 쌓였고 결과 검수와 피드백에 걸리는 시간이 점점 길어졌다.
- 원인: 어떤 결정을 에이전트가 해도 되는지 정해져 있지 않았다. PM에서 개발로 일이 넘어가는 연결이 없어 HJ의 메시지가 매번 실행 트리거가 됐다.
- 다음부터: 결정 권한을 문서로 정한다. 승인을 기다리며 멈추지 않는다. 작업 인계는 Issue 라벨로 한다.

## 2026-11-10 팀 셋업: 갱신할 수 없는 곳에 문서를 뒀다

- 무슨 일: 인수인계와 누적 규칙을 구글 문서에 두었는데 문서 본문을 고칠 도구가 없어 갱신할 수 없었다.
- 원인: 연결된 도구로 무엇을 고칠 수 있는지 확인하지 않고 저장 형태를 정했다.
- 다음부터: 저장 형태를 정하기 전에 그 역할의 에이전트가 읽고 쓸 수 있는지부터 확인한다. CTO의 문서는 저장소에 둔다.

## 2026-11-12 개발 세팅: 프레임워크가 역할 문서를 자동 수정했다

- 무슨 일: Next.js 16.4.6 개발 서버가 AGENTS.md에 프레임워크 안내 블록을 자동 추가했다. 생성된 블록만 제거했다.
- 원인: 개발 서버의 agentRules 기본 동작을 시작 전에 확인하지 못했다.
- 다음부터: 기존 팀 규칙이 있는 저장소는 next.config.ts에서 agentRules=false로 자동 생성을 끄고, 서버 실행 후 문서 diff도 검사한다.

## 2026-11-12 Windows 검증: 한글 파이프 입력이 검사 결과를 왜곡했다

- 무슨 일: HTTP 응답은 정상이었지만 PowerShell에서 Node로 전달한 한글 비교 문자열이 변환돼 검사가 실패했다. Unicode 이스케이프로 다시 검사해 통과했다.
- 원인: 셸 파이프 문자 인코딩과 HTTP 본문 인코딩을 구분하지 않았다.
- 다음부터: 한글이 포함된 검증은 UTF-8 파일이나 Unicode 이스케이프를 사용하고 실패 원인을 앱과 검사 도구로 나눠 확인한다.

## 2026-11-12 Discord: 소라가 자기 멘션 ID를 잘못 알았다

- 무슨 일: 소라가 자기 ID(1570101648054034522)를 Cap의 ID로 판단해, HJ가 소라를 멘션한 메시지 여러 개에 답하지 않았다. HJ에게도 ID를 거꾸로 안내했다.
- 원인: 그 멘션에 Codex_bot이 답한 기록만 보고 ID의 주인을 추정했다. 봇 ID를 문서로 확인하지 않았다.
- 다음부터: 봇 ID는 CLAUDE.md에 적힌 값만 쓴다. ID가 불확실하면 추정하지 말고 HJ에게 묻는다.

## 2026-11-12 소라와 Cap이 같은 작업 폴더를 썼다

- 무슨 일: 소라가 main에 올린다고 생각한 기획서 커밋이 Cap이 체크아웃해 둔 issue-2, issue-4 브랜치에 들어갔다.
- 원인: 두 에이전트가 같은 폴더를 공유했고, 소라가 커밋 전에 현재 브랜치를 확인하지 않았다.
- 다음부터: 소라는 별도 작업 트리에서 문서를 고치고, 커밋 전에 브랜치를 확인한다.

## 2026-11-12 동시 병합: 닫힌 PR 브랜치에 문서 커밋을 추가했다

- 무슨 일: PR #5가 다른 세션에서 병합되는 동안 추가 문서 커밋을 기존 브랜치에 올렸다. 이후 최신 main에 필요한 내용만 대조 반영했다.
- 원인: 원격 PR 조회와 푸시 사이에 상태가 바뀌었다.
- 다음부터: 병합 직전 원격 상태를 재확인하고, 이미 병합된 경우 최신 main의 변경을 보존해 후속 문서를 정리한다. 같은 체크아웃에서 동시에 커밋하지 않는다.

## 2026-11-13 목업: 되묻기 답변 시 편집 중 초안을 보존한다
