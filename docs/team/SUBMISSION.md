## 꼭 지킬 것

- 회사 내부 문서, 영업비밀, 고객 정보, 개인정보를 쓰지 않는다. 시연 데이터는 가상 데이터나 공개 데이터만 쓴다.
- 아이디어 제공자의 실명과 카톡 원본은 영상, 기획서, 저장소에 넣지 않는다.
- 기존 결과물을 발전시킨 부분이 있으면 README와 기획서에 기존 부분과 새로 만든 부분을 나눠 적는다. 미리내는 11-12부터 새로 작성한다.
- 개발에는 신청서에 등록한 팀원만 참여한다.

## 우리 쪽에 주는 영향

- 심사위원은 자기 키로 로컬에서 실행한다. 문의함의 실시간 판정은 `.env.local`에 `LINER_API_KEY`와 `LINER_MODE=live`를 넣어야 하고(README "심사용 로컬 실시간 판정"), 단일 검색 화면(`/research`)은 기본 `auto`라 키만 있어도 실제 검색한다. 공개 주소(https://onemorestep-wheat.vercel.app/)는 저장된 결과 전용이다(크레딧 사용 없음, 메일 없음).
- 판정 결과는 둘로 나눠 보인다: 시연 30건(저장 30/30, 실시간 25/30, PR #44 보정 기준)과 평가 세트 70건(HJ 블라인드 정답, #32에서 측정). 영상 장면 7과 기획서가 같은 수치를 쓴다.
- 저장소 공개 전환 전에 git 이력 전체에서 키와 개인정보를 검사한다.
- 기획서는 1~2페이지 PDF다. `docs/product/PLAN.md`에서 요약해 만든다.
