## 기술 결정

| 선택 | 이유 |
|---|---|
| TypeScript | 브라우저와 서버에서 조사 결과 형식을 공유하고 응답 검증을 한 곳에서 수행한다. |
| Next.js 16 App Router + React 19 | 화면과 서버 API를 하나의 앱으로 실행해 별도 백엔드와 CORS 설정을 줄인다. |
| Node.js 24 + npm 잠금 파일 | 현재 환경의 Node 24를 기준으로 재설치를 재현한다. |
| Liner Web Search + 기본 fetch | 조사 출처를 핵심 기능에 직접 사용하며 추가 SDK 없이 한 엔드포인트로 검증한다. |
| 기본 예시 모드, 서버에서만 키 사용 | 계정 없이 로컬 실행 가능하며 검색 실패가 시연을 멈추지 않는다. |
| CSS 기본 스타일 | Issue의 제외 범위인 제품 디자인을 앞서 구현하지 않는다. |
| 배포 후보: Node 서버 또는 Vercel | Next.js 표준 실행을 유지한다. 선택과 실행, 비용 승인은 HJ 관문으로 남긴다. |
| DB·로그인·OAuth 없음 | 오늘은 영속 상태가 필요 없다. 반응 저장 방식은 후속 Issue에서 정한다. |

공식 근거: [Next.js 설치 및 시스템 요구](https://nextjs.org/docs/app/getting-started/installation), [Node 서버 배포](https://nextjs.org/docs/app/guides/deploying-to-platforms), [Liner 사양](LINER_API.md).

## MVP 데이터 흐름

```text
가상 일정 · 할 일 · 메모
        ↓
입력 검증 → 카드 후보 추론/규칙 → 우선순위로 최대 3장 선택
                                  ↓
                          카드별 조사 질의 구성
                                  ↓
                    서버 Liner Web Search → 출처 검증
                                  ↓
                   조사 결과 또는 명시된 예시 → 카드 화면
                                  ↓
                       했어요 / 나중에 / 필요 없어요
```

오늘 구현한 경로는 `질의 입력 → POST /api/research → Liner 또는 예시 → 출처 표시`다. 나머지는 후속 Issue 범위다. 개인화 학습을 구현했다고 표현하지 않는다.

## 경계와 데이터

- `src/app`: 개발 확인 화면과 API Route. 환경변수는 Route에서만 읽는다.
- `src/lib/research.ts`: 입력 검증, 외부 호출, 응답 정규화, 예시 전환. 테스트에서 fetch를 대체할 수 있다.
- `ResearchResult`: live/sample 모드, 입력 질의, 예시 질의(해당 시), 안내 문구, 출처 배열.
- 기본 예시는 공개 문서에 대한 수작업 예시이며 외부 검색 캐시나 실측 성과 데이터가 아니다.
- 개발 서버는 127.0.0.1에 바인딩한다. 외부 공개 전 인증/호출 예산/요청 제한 검토가 필요하다.

## 공수 추정과 위험

아래는 Cap의 가정 기반 추정(개발일)이며 실제 연동 없는 단일 사용자 데모 기준이다. PM이 범위를 줄여 조정한다.

| 기능 | 공수 | 위험 및 대응 |
|---|---|---|
| 가상 일정·할 일·메모 입력 | 0.5일 | 날짜/시간대 혼선: Asia/Seoul 기준 고정 샘플 |
| 카드 최대 3장 생성·우선순위 | 1~1.5일 | 누락/과잉 추론: 고정 시나리오 규칙부터 검증 |
| 카드별 조사·출처 연결 | 1일 | 네트워크/부정확한 자료: 출처와 예시 상태 분리 |
| 반응 버튼·상태 유지 | 0.5일 | 지속 학습으로 오인: 상태 저장으로 범위를 명확히 함 |
| 통합 화면·오류·시연 검증 | 1~2일 | 외부 지연: 예시 모드로 끝까지 시연 가능 |
| 합계 | 4~5.5일 | PM 검토 후 기능 Issue로 분할 |

범위 추천은 반응 상태 저장까지다. “반응으로 다음 제안을 고친다”는 개인화 학습은 공수 미산정이며 PM 결정 전 확정 범위로 취급하지 않는다. 대안 ① 고정 규칙에서 보류/완료/제외 반영 ② 이번 MVP는 현재 카드 상태만 저장, 개인화는 로드맵. 추천 ②로 준비한다.

실제 캘린더/메일 연동은 인증과 데이터 접근 때문에 시연 위험이 커 현재 기획대로 제외한다. 대안 ① 가상 입력 편집 ② 공개 JSON 파일 가져오기. 추천 ①이다. 배포·유료 가입·결제는 수행하지 않았다.

## 오늘 완료 기준과 검증 방법

1. `npm ci`로 설치 후 `npm run dev`로 로컬 화면을 연다.
2. 키 없이 질의를 제출하면 출처 2건과 예시 안내가 표시된다.
3. 테스트는 실시간 응답 정규화, 키 누락, 401/402/429/5xx, 네트워크, 시간 초과, 잘못된 JSON/URL과 입력 오류를 확인한다.
4. lint, 타입 검사, 테스트, 프로덕션 빌드가 통과해야 PR 검토를 요청한다.

실제 API 성공 여부는 [검증 상태](LINER_API.md)를 따른다. 예시 동작만으로 대회 API 활용 조건을 충족했다고 판정하지 않는다.

## 설치 시 확인한 제한

2026-11-12 npm audit 결과 프로덕션 의존성 취약점은 0건이었다. 개발용 TypeScript ESLint 하위 minimatch 관련 중간 등급 7건은 호환 범위의 npm audit fix로 해소되지 않았다. 강제 버전 교체는 하지 않았으며 PM 검토 시 후속 우선순위를 정한다. [해당 보안 권고](https://github.com/advisories/GHSA-g3hv-75wg-m249)

Next.js 개발 서버가 기존 AGENTS.md를 자동 변경하지 않도록 agentRules=false를 설정했다. 브라우저 연결 도구는 시간 초과로 사용할 수 없어 이번 세션의 실행 검증은 실제 HTTP 요청과 자동 테스트 기준이다. 브라우저 클릭 및 화면 시각 검증은 확인하지 못했다.
