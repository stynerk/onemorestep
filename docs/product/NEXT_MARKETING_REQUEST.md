# 다음 확장 버전 후보: 마케팅 협조 요청 에이전트

작성: 서비스PM Tony, 2026-11-18. 출처: HJ가 겪은 실제 업무(회사명·사내 수치 없이 일반화). 상태: MVP 범위 밖, 다음 버전 후보.

## 판단

MVP(세일즈 리드 포워딩)와 개념은 충돌하지 않는다. 같은 틀을 쓴다. 하지만 마감까지 7일이라 구현 범위에 넣으면 리드 흐름의 완성도가 떨어진다. 그래서 **MVP에는 넣지 않고, 기획서 확장성 장과 영상 장면 7에 "같은 틀의 두 번째 적용"으로만 보인다.**

## 문제

- 마케팅팀에 협조 요청이 아주 많이 온다. 처음엔 메일로 받다가 자동화 폼으로 바꿨다.
- 폼은 워크플로를 기계적으로 고정해 둔 것이라 풀리지 않는 요청이 생긴다.
- 담당자가 바뀌면 워크플로 수정·업데이트가 매우 제한적이라 유지보수가 어렵다.
- 요청하는 세일즈는 입력할 것이 많아 제목과 간단한 내용 외에는 자세히 쓰지 않는다. 마케팅이 다시 물어봐야 한다.

## 에이전트가 하는 일

1. 접수는 폼으로 받되, 빠진 정보는 챗봇 대화로 요청자에게 받는다.
2. 반복되는 요청 유형은 템플릿으로 만들어 제안한다.
3. 템플릿으로 노출할 콘텐츠 초안을 구성하고 요청자와 협의한다.
4. 협의 결과를 마케팅 담당자에게 승인 요청한다. 담당자는 리뷰하고 승인만 한다.
5. 미승인이면 사유(콘텐츠 보완 필요, 처리 여력(capa) 부족 등)에 맞춰 다시 구성해 제안한다.
6. 거부면 사유를 입력받아 요청자에게 결과를 공유한다.

## MVP와 같은 틀

| 단계 | 세일즈 리드 (MVP) | 마케팅 협조 요청 (다음 버전) |
|---|---|---|
| 유입 | 온라인 리드 | 폼 요청 |
| 부족한 정보 | 소속 기관을 Liner로 확인 | 요청자와 대화로 보충 |
| 판단 | 유효 / 애매 / 무효, 딜러 추천 | 요청 유형, 템플릿, 콘텐츠 초안 |
| 사람 | 담당자가 결정 카드로 승인 | 담당자가 리뷰하고 승인 |
| 거절·실패 | 딜러 미응답 → 재배정 | 미승인 사유 → 재구성, 거부 → 사유 공유 |
| 기록 | 딜러 deal / no deal이 다음 순위에 | 승인·미승인 사유가 다음 템플릿에 |

공통 원칙: **AI가 준비하고 근거를 붙이고, 사람은 승인만 하고, 거절 사유가 다음 판단의 재료가 된다.** 담당자가 바뀌어도 규칙이 폼 설정이 아니라 기록과 템플릿에 남아 유지보수 문제가 줄어든다.

## Liner 쓰는 지점 (예상)

- Model API: 대화로 정보 보충, 유형 분류, 콘텐츠 초안 작성.
- Search API: 콘텐츠에 넣을 공개 자료·사례·근거 찾기.
