# 미리내 기획서 (초안 v0.1)

작성: PM 소라, 2026-11-12. 상태: 초안. `[HJ]` 표시는 HJ의 확인이나 입력이 필요한 곳이다.

배점: 문제 정의 30, 완성도 30, Liner API 활용 20, 확장성과 임팩트 20.

## 1. 문제 정의 (30점)

- 한 줄: 일을 하는 사람은 "지금 묻지 않았지만 미리 해 뒀어야 할 일"을 놓친다. 지금의 AI 도구는 물어야 답하므로 이 공백을 메우지 못한다.
- HJ의 일화: `[HJ]` 한두 문장. 언제, 무엇을 놓쳤고, 무엇을 미리 알았다면 달랐는지.
- 가정: 놓치는 일의 대부분은 일정, 할 일, 최근 문서처럼 이미 가진 정보에서 추론할 수 있다. 근거는 HJ 일화와 테스터 인터뷰로 보강한다(수치는 아직 없음).

## 2. 대상 사용자

- 주 대상: 여러 일을 동시에 굴리는 지식 노동자(기획자, PM, 1인 창업자). 일정과 마감이 많고 조사할 거리가 자주 생긴다.
- 테스터: HJ의 지인. 2주 참여 여부는 `[HJ]` 확인 전.

## 3. 핵심 시나리오 (데모 후보, 관문 2)

1. 사용자가 오늘의 일정, 할 일, 최근 메모를 미리내에 연결한다(데모는 가상 데이터).
2. 사용자가 아무것도 묻지 않아도 미리내가 "미리 챙길 일" 카드 3장을 낸다.
   - 예: "내일 10시 A사 미팅. A사의 최근 발표 3건을 정리해 뒀어요" (Liner API로 조사, 출처 포함)
   - 예: "금요일 마감 보고서에 필요한 시장 자료가 아직 없어요. 초안 자료를 모아 뒀어요"
   - 예: "다음 주 출장 서류 제출 마감이 오늘이에요"
3. 사용자는 카드마다 "했어요 / 나중에 / 필요 없어요"를 누르고, 미리내는 카드 상태를 저장해 처리한 카드를 다시 내지 않는다. 반응으로 다음 제안을 고치는 개인화 학습은 로드맵이다(PR #5, PM 결정).

## 4. MVP 범위

| 포함 | 근거 |
|---|---|
| 가상 일정, 할 일, 메모 입력 | 실제 연동 없이도 핵심 가설(먼저 알려 주면 가치가 있다)을 보여 줄 수 있다 |
| 미리 챙길 일 카드 생성(하루 3장) | 데모의 중심 장면 |
| 카드별 Liner API 조사 결과와 출처 | Liner API 활용 20점, 핵심 기능에서 쓰여야 한다 |
| 카드 반응 버튼 | 완성도와 확장성 이야기를 받친다 |

| 제외 | 근거 |
|---|---|
| 실제 캘린더, 메일 연동(OAuth) | 공수 대비 데모 가치 낮음, 인증 실패 위험. 확장성 장에서 로드맵으로만 말한다 |
| 알림 푸시, 모바일 앱 | 데모는 웹 화면 하나로 충분 |
| 다중 사용자, 로그인 | 핵심 가설과 무관 |

공수와 기술 선택은 Cap의 추정을 받은 뒤 이 표를 줄여 맞춘다.

## 5. 성공 지표 (가정)

- 데모: 입력부터 카드 3장까지 끊김 없이 1분 안에 보여 준다.
- 테스터: 카드 중 "했어요"나 "도움 됐어요" 비율. 목표치는 테스터 확정 후 정한다(가정).
