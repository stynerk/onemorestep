## One More Step: 수많은 리드와 문의 속에서 가장 확실한 리드만 전달하는 세일즈 에이전트

### 1. 누가, 어떤 문제로, 얼마나 불편한가

**세일즈 담당자는 문의마다 진짜 기관인지, 어느 딜러에 맡길지를 전화와 감으로 정한다.**

**누가:** 딜러 판매가 주력인 제조사(예: 가상의 의료기기 제조사 Medicom)의 본사 세일즈 담당자.

**지금 일하는 방식:** 홈페이지 문의(리드)가 들어오면 담당자가 거의 모든 리드에 전화를 걸어 진짜 고객인지 확인하고, 그 지역 딜러 중 한 곳을 골라 넘긴다. 팀 대표(HJ)가 제조사 세일즈 조직에서 직접 겪은 업무 흐름을 회사명과 내부 수치 없이 일반화했다.

**문제 세 가지:**
1. **소음이 신호를 묻는다.** 문의의 상당수는 스팸, 영업 제안, 학생 과제, 구직, 허위 정보다. B2B 폼 제출 100만 건 이상을 분석한 자료에서 영업 전에 걸러진 비율은 18.7~37.7%, 대기업 대상은 71.2%였다(RevenueHero, 2025). Salesforce도 리드가 영업 단계(SQL)까지 가는 비율을 10~40% 정도로 보고, 대부분의 리드는 그 단계에 가지 못한다고 설명한다(Salesforce, "What Is a Sales Qualified Lead?", 2026). One More Step은 리드 100건 중 약 20건만 유효하다고 **가정**한다(팀 대표의 실무 경험).
2. **늦으면 기회가 사라진다.** 미국 기업 2,241곳에 웹 문의를 보낸 조사에서 1시간 안에 답한 곳은 37%였고, 1시간 안에 연락한 기업은 1시간 늦은 기업보다 의사결정자와 대화할 가능성이 약 7배 높았다(Harvard Business Review, 2011). 비적격 리드에 전화를 거는 동안 진짜 고객은 기다린다.
3. **판단이 사람에게 묶여 있다.** "진짜 고객인가"와 "어느 딜러가 믿을 만한가"는 담당자 개인의 경험으로 정한다. 사람마다 판단이 다르고, 담당자가 바뀌면 경험이 사라진다. 예전에 거래한 딜러에게 넘겼는데 대응이 느려 기회를 놓치기도 한다.

### 2. 해결 방식

**원칙: AI가 준비하고 근거를 붙이고, 사람은 승인만 하고, 결과가 다음 판단의 재료가 된다.**

담당자가 문의함에서 "선별 시작"(또는 리드별 선별)을 누르면, One More Step이 **선별 → 넘길 곳·딜러 추천 → 결정 카드**를 준비하고 담당자에게는 추천 승인만 요청한다.

| 단계 | One More Step이 하는 일 |
|---|---|
| 선별 | 소속 기관이 실재하는지, 소재지가 리드 국가와 맞는지, 이메일 도메인이 기관 공식 도메인과 맞는지를 공개 정보로 확인하고, 메모의 의도(구매·제휴·영업·과제)를 읽어 **유효 / 애매 / 국가 확인 / 제휴 확인 / 무효**로 나눈다. 확인된 근거에는 링크와 검색 시각을 붙인다. 넘길 곳을 함께 표시한다: 유효는 국가 딜러, 애매·국가 확인·제휴 확인(사칭 의심 포함)은 권역 세일즈팀, 채용 문의는 인사팀, 그 밖의 무효는 넘기지 않음 |
| 딜러 추천 | 리드 국가 딜러의 **최근 90일 전달 결과(deal / no deal / 미응답)**로 순위를 매기고 이유를 보인다. 이력이 적은 신규 딜러만 있으면 지역 담당자에게 먼저 확인한다 |
| 결정 카드 | "이 리드를 ○○ 딜러에게 넘길까요?" + 근거 3개. 추천이 맞으면 **승인** 한 번이고, 아니면 **딜러 변경**(후보 선택과 사유 입력) / **전화 필요** / **무효 처리**를 고른다. 승인하면 딜러용 요약 메일 이벤트가 생긴다(시연·테스트 환경에서는 테스트 수신함으로만 가고, 공개 시연 주소는 메일을 보내지 않는다) |

- 무효는 이유와 함께 묶어 한 번에 확인하고, 전화는 근거가 부족한 "애매" 건에만 건다. 모든 전화를 없앤다고 주장하지 않는다.
- 국가가 어긋난 리드에는 국가 확인 메일을, 제휴 제안에는 세부 사항 요청 메일을 만든다(테스트 수신함으로만 발송).
- 딜러가 응답 기한을 넘기면 One More Step이 다음 딜러로 재배정을 제안하고, 미응답 기록이 쌓이면 다음 리드의 딜러 순위가 바로 바뀐다. **제조사만 가진 기록이 판단의 재료가 되는 반복 루프**다.

**사람 손이 가는 건수 (시연 30건 기준 계산):** 지금 방식에서는 담당자가 거의 모든 리드에 전화한다(팀 대표의 실무 경험, **가정**). One More Step에서는 무효 11건을 이유와 함께 한 번에 처리하고, 유효 8건은 승인 한 번으로 넘기고, 국가 확인 3건과 제휴 확인 2건은 확인 메일로 처리한다. 사람이 판단해야 하는 건은 애매 6건뿐이고, 이 6건도 화면의 질문("이 메일을 ○○ 기관 것으로 볼까요?" 등)에 먼저 답한 뒤 모르는 것만 전화한다. 사실을 확인한 담당자의 답은 기록돼 다음 리드에 "이전 담당자 확인" 근거로 다시 쓰인다. 도메인 소유 확인은 같은 기관·같은 도메인의 리드에, 소재지 확인은 같은 기관의 리드에 쓰인다. 사칭으로 무효·전화로 확인 같은 처리 답과 사칭 의심 리드를 정상으로 승인한 답은 그 리드에만 적용된다. **전화 대상이 30건에서 최대 6건으로 준다.** 건수를 센 것이고 작업 시간을 잰 것은 아니다.

**대표 결과: 엔진이 한 번도 보지 않은 블라인드 30건 (2026-11-23):** 엔진 커밋을 먼저 고정한 뒤 세트를 열었고, 실무자가 매긴 정답과 비교했다. 실제 Liner 호출 84회(검색 46, 모델 의도 29, 모델 도메인 판단 9)로 측정했다.
- 선별 **17/30(57%)**, 넘길 곳 **21/30(70%)**.
- **유효 리드를 무효로 버린 건 0건, 유효가 아닌 리드를 유효로 올린 건 0건.** 틀린 13건은 모두 "애매"로 사람(권역 세일즈팀)에게 넘어갔다. One More Step은 틀릴 때 사람에게 넘기는 쪽으로 틀린다.
- 한계: 정답이 유효인 11건 중 8건, 국가 확인 2건, 제휴 확인 3건이 애매로 갔다. 주원인은 기관의 사이트 도메인과 메일 도메인이 다를 때 소유 관계를 확인하지 못하는 것(예: ucsf.edu와 ucsfhealth.org)과 소재지를 한 나라로 특정하지 못하는 것이다.

**시연 30건과 개발용 평가 70건:** 시연 30건은 저장된 검색 근거로 선별·넘길 곳 30/30이다(선별 규칙과 함께 설계한 세트). 개발용 평가 70건은 처음 블라인드 측정에서 33/70(원본 정답 기준 23/70, 가상 기관 11건 정답 정정)이었고, 실패 원인을 고친 뒤 같은 검색 응답을 재생해 52/70이 됐다. 이 52/70은 평가 결과를 본 뒤의 수치라 블라인드 결과로 내세우지 않는다. 그래서 위의 새 블라인드 30건을 따로 만들어 측정했다.

### 3. Liner API 활용

| 쓰는 곳 | API | 역할 |
|---|---|---|
| 소속 기관 조사 | Liner Search | 리드마다 "기관명 + 국가", "기관명 + 업종"을 검색해 기관 실재, 소재지, 공식 도메인을 확인한다. 유효 선별의 외부 근거다 |
| 사칭 걸러내기 | Liner Search 결과 | 검색으로 확인한 공식 도메인과 리드 이메일 도메인을 대조해 닮은꼴 도메인을 사칭 의심으로 표시해 권역 세일즈팀이 결정하게 넘긴다 |
| 문의 의도 판단 | Liner Router(모델) | 메모를 읽고 구매·제휴·채용·학생 과제·영업 제안·스팸 중 의도를 고르고, 근거가 된 메모 문장을 인용한다. 정해진 표현 목록으로는 놓치던 문의(다른 언어, 처음 보는 표현)를 잡는다 |
| 도메인 소유 판단 | Liner Router(모델) | 규칙이 메일 도메인을 확인하지 못할 때만, 이미 받은 검색 결과를 읽고 "이 도메인이 이 기관 것인가"를 판단하며 검색 결과 원문과 URL을 인용한다 |
| 담당자 질문 | Liner Router(모델) | 애매 리드의 질문 문구를 만든다. 화면의 근거(확인한 것·확인하지 못한 것)는 앱이 실제 선별 기록에서 채운다. 선택지는 정해져 있고, 모델 호출이 실패하면 기본 문구를 쓴다(공개 시연은 기록 재생) |
| 마케팅 채널 초안 | Liner Router + Search | 마케팅 협조 요청의 채널별 초안을 모델이 쓰고, 사실 근거는 검색 링크로 붙인다. 근거가 없는 문장은 "확인 필요"로 표시한다 |

- **AI가 판단하고 규칙이 지킨다.** 모델의 답은 인용이 실제 메모나 검색 결과에 있을 때만 쓴다. 모델 혼자서는 유효를 만들 수 없고, 가상 기관·사칭 의심·무료 메일 선별을 뒤집을 수 없다. 모델 호출이 실패하면 규칙으로 선별한다.

- **Liner가 빠지면 선별이 성립하지 않는다.** 소속을 공개 정보로 확인하지 못하면 One More Step은 "유효"를 주지 않는다. 그래서 외부 근거가 없으면 판단이 다시 담당자의 경험으로 돌아간다.
- 실제 키로 공개 기관 5곳 × 2질의를 검색해 10회 모두 정상 응답을 받았다. 실재·업종·소재지·공식 도메인 네 항목을 모두 확인한 곳은 3곳이었다(2026-11-18).
- 검색 실패나 시간 초과는 "외부 확인 실패"로 표시하고 애매로 둔다. 화면은 멈추지 않는다.

### 4. 확장 가능성

- **딜러·대리점망을 가진 B2B 판매 전반 (구현된 구조 그대로):** 리드가 기관·기업 소속이고 딜러·대리점·리셀러가 있는 업이면 같은 엔진이 그대로 돈다(산업재 총판, 분석 장비, B2B SaaS 리셀러). 선별·추천 흐름은 그대로 재사용하고, 딜러 초기 데이터(딜러 표)와 정책값(집계 기간 90일, 이력 기준 3건, 가중치, 나라→권역 매핑)만 조정한다. 정책값은 정책 파일 하나에 모여 있다. **공개 시연에서 업종을 "B2B SaaS"(가상 회사 Flowline, 나라별 리셀러 파트너 7곳)로 바꿔 직접 확인할 수 있다.** 선별 규칙은 그대로 두고 데이터와 정책만 바꿔 리드 10건을 돌렸을 때 선별 10/10이 나왔다(이 10건은 개발 중에 본 세트라 블라인드 수치는 아니다).
- **조직의 기억:** 신입 담당자도 같은 근거로 판단하고, 결정과 딜러 결과가 기록으로 남아 다음 추천을 바꾼다. 개인 경험이 조직의 자산이 된다.
- **같은 원칙의 다른 직무 (구현, 공개 시연에서 확인 가능): 마케팅 협조 요청.** 본사 세일즈가 마케팅에 자료·홍보를 요청하면, One More Step이 딜 규모·단계(40), 마감일(30), 지역 전략(20), 반복 요청(10)으로 점수와 이유를 붙여 순서를 정하고 같은 주제 요청은 묶자고 제안한다. 마케팅 수신 동의 이메일·LinkedIn·Facebook·Instagram·블로그 중 맞는 채널을 추천하고, Liner Router가 채널별 초안을 쓰고 Liner Search 근거 링크를 붙인다. 효능·안전 단정, 근거 없는 수치 같은 의료기기 표현은 경고로 표시한다. 실무자는 사유를 남기고 순위를 바꿀 수 있고(AI 점수와 사람 순위를 함께 기록), 발송·게시는 하지 않고 초안까지만 준비한다. 세일즈가 리드를 연결해 요청을 넣으면 지역·딜 단계가 문의함 기록에서 채워지고, 마케팅은 접수 → 진행 → 검토 → 완료로 처리하며(마감 임박·초과 경고), 완료하면 캠페인 코드가 나온다. **효과는 그 코드로 들어온 실제 리드를 One More Step이 선별한 유효 비율로 잰다.** 시연에서 Instagram 캠페인은 리드 6건을 모았지만 유효 0건, LinkedIn은 5건 중 3건이 유효였고, 이 효과가 다음 요청의 채널 추천 옆에 보인다. 마케팅의 목표는 리드의 양이 아니라 세일즈를 위한 양질의 리드다. 시연 요청·캠페인·유입 경로와 지역 가중치는 가상 데이터·가정이다(평가 70건의 유입 경로는 고정 규칙으로 배정).

공개 시연: https://onemorestep-wheat.vercel.app/ (시연 계정 ID `medicom`, PW `1234!`. 회원 구조는 본선·서비스 진행 시 추가한다.)
