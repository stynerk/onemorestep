# 가상 테스트 회사

2026-11-13 HJ 요청으로 추가했다. 데이터 원본은 scenarios.js다. 기존 코드나 실제 기업 자료를 복제하지 않고 새로 작성한 테스트 픽스처이며 실제 수요·운영·안전 검증 결과가 아니다.

## 자율주행 차량 운영 관리: 루프오토(가상)

접속: https://stynerk.github.io/onemorestep/?scenario=autonomy

상단 ‘테스트 회사’에서 기존 소상공인 AI 서비스와 전환한다. 기존 회사의 저장 키는 유지하고 자율주행 회사는 별도 키를 사용한다. 저장한 입력·준비 상태·초안·회사 자료·업무 지도는 섞이지 않는다. 저장 전 편집은 전환 전에 저장해야 한다.

| 항목 | 가상 설정 |
|---|---|
| 제공 가치 | 차량 운영사의 배차·관제·정비·운영 이력 관리 |
| 고객 후보 | 자율주행 차량 운영사·운수 사업자 |
| 현재 단계 | 법인 설립, 관제 시제품, 실증 파트너 탐색, 상용 운영 전 |
| 목표 | 실증 범위 합의와 첫 파일럿 제안서 준비 |
| 고민 | 완성차·운수 사업자 중 어떤 고객과 먼저 검증할지 |
| 제약 | 관제·데이터 개발 가능, 차량·현장 파트너·검토 체계 협의 전 |
| 비교 대상 | 가상 플릿브릿지(관제·정비 이력 관리) |

주행 판단·차량 제어는 기술 협력사의 영역으로 가정해 운영 관리 서비스의 준비를 테스트한다. 이는 실제 차량을 운행하는 절차나 허가·안전 요건 안내가 아니다.

## 화면별 데이터

- 회사 설정: 위 6개 질문과 가상 시나리오 안의 사실/가설 구분. 사실 표시는 현실에서 확인했다는 뜻이 아니다.
- 회사 자료: 제품 범위, 관제 시제품 검토 이력, 분산된 운영 기록에 대한 미검증 고객 가설 등 3개. 실제 사내 자료·개인정보·API 키는 없다.
- 업무 지도: 실증 파트너 미팅(2026-11-18), 제안서 내부 검토(2026-11-23)라는 가상 일정 2개. 실제 행사나 공고 마감이 아니다. 반복 업무 3개와 관심 주제 5개.
- 스타트업 지원: 가상의 서울 지역 모빌리티 실증 협력 프로그램. 협력 대상·지역·역할과 제안서 항목을 확인한다.
- 시장·경쟁사: 가상 경쟁사의 정비 이력 통합 발표. 기능 비교와 운영사 고객 인터뷰 질문을 준비한다.
- 우리 회사: 시제품 화면 검토 뒤 미정인 운영 예외 대응의 책임·승인·검증 범위를 협의한다. 준비 중 상태와 체크 1/3은 테스트용 초기값이다.
- 초안: 실증 협력 제안서 목차 / 운영사 인터뷰 질문 / 파일럿 사전 협의 질문. 해당 테마 회사 자료의 원문 발췌를 함께 표시한다.

선택한 회사에서 ‘목업 데이터 초기화’를 누르면 그 회사의 가상 초기값으로 돌아간다. 자율주행 시나리오에서는 자료 3개·일정 2개·준비 중 과제도 복원한다. 다른 회사의 저장값은 바꾸지 않는다.

## 검증과 남은 제한

- 실제 Chrome에서 자율주행 프로필·카드·지원 초안·자료 연결, 지도 일정/관심 주제/준비 중 과제, 기존 회사로의 전환을 확인했다.
- 실제 loadState 함수를 격리 실행해 회사별 저장 키, 각 회사 수정값 유지, 고정 카드 분리와 알 수 없는 시나리오의 기존 회사 복귀를 검사했다.
- 이후 브라우저 연결이 시간 초과·연결 종료로 중단돼, 왕복 전환의 전체 UI 반복 검사와 새 선택 메뉴의 모바일 시각 검증은 완료하지 못했다. 모바일 선택 메뉴는 한 열 CSS를 적용했다. 검증하지 않은 항목을 통과로 보고하지 않는다.
- 자동 검색·조건 재판단·저장 초안 재검토·실행 결과 피드백은 기존 FLOW_AUDIT.md의 미구현 상태 그대로다. 시나리오 선택에 따라 미리 만든 데이터 묶음이 바뀌는 것을 개인화나 재판단 구현으로 취급하지 않는다.
