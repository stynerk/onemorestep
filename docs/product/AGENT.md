# 미리내 에이전트: 차별성, 핵심 기능, 역할과 워크플로우, 기대효과와 평가

## 한 줄 정의

미리내는 초기 창업자 곁에서 **먼저 챙겨 주는 경험 많은 공동창업자**다. 회사 모델에 비춰 세상의 변화(지원사업, 시장·경쟁사, 단계별로 챙길 일)를 찾아 "지금 할 일"로 바꿔 준다.

근본 문제(HJ 확인, 2026-11-13): 초기 대표는 무엇을 모르는지 모르고, 정보를 "내 상황이면 지금 뭘 해야 하지?"로 바꿔 줄 사람이 옆에 없다.

## 차별성

| 지금의 대안 | 한계 | 미리내 |
|---|---|---|
| 뉴스레터, 뉴스 | 모두에게 같은 글. 알려 주고 끝난다 | 내 회사 기준으로 고르고, 할 일 한 줄까지 낸다 |
| 검색, 대화형 AI | 내가 물어야 답한다. 모르는 건 물을 수 없다 | 묻기 전에 먼저 찾아 온다 |
| 지원사업 모음 사이트 | 지원사업만 다룬다. 자격 대조와 준비는 내 몫 | 지원·시장·회사 일을 한곳에서, 자격 대조와 준비 목록까지 |
| 멘토, 액셀러레이터 | 좋지만 드물고 비싸며 매일 곁에 있지 않다 | 매일 아침, 내 사정을 기억하는 상태로 |

미리내만의 다섯 가지:

1. **먼저 말한다.** 사용자가 묻지 않아도 매일 아침 찾아 온다.
2. **내 회사 기준이다.** 회사 모델(목표, 단계, 자격, 경쟁사)에 대 보고 "왜 나에게 해당하는지"를 말한다.
3. **알림이 아니라 할 일이다.** 모든 카드에 할 일 한 줄과 준비물이 붙는다. 할 일이 없으면 카드를 내지 않는다.
4. **출처로 믿게 한다.** 날짜·금액·자격은 Liner로 찾은 원문 출처와 함께만 보여 준다.
5. **쓰면서 자란다.** 모르는 건 카드에서 되묻고, 답과 반응이 회사 모델에 쌓인다.

## 핵심 기능 (MVP)

| 기능 | 하는 일 | 화면 |
|---|---|---|
| 3분 설정 | 질문 6개로 회사 모델의 씨앗을 만든다: 한 줄 소개, 고객, 단계·등록 여부, 지역·대표 조건, 3개월 목표, 경쟁사 | 처음 설정 |
| 아침 브리핑 | 오늘 가장 중요한 일 1개와 테마별 한 줄 | 메인(컨셉 C) |
| 테마 보기 | 시장 동향·경쟁사 / 스타트업 지원 / 우리 회사에 필요한 것 | 더 보기(컨셉 B) |
| 카드 상세 | 자격 대조, 이번 주 할 일 체크리스트, Liner 출처 | 카드 상세 |
| 되묻기 | 판단에 필요한 정보를 카드에서 묻고 회사 모델에 저장 | 카드 안 |
| 반응과 추적 | 했어요/나중에/필요 없어요, "준비 중" 진행률, 다가오는 마감 | 메인 |

제외: 로그인, 캘린더·메일 연동, 지원사업 사이트 크롤링, 푸시 알림, 반응 기반 개인화 학습(로드맵).

## 에이전트의 역할

| 한다 | 하지 않는다 |
|---|---|
| 지켜보기: 회사 모델에서 테마별 질의를 만들어 Liner로 찾는다 | 대신 신청하거나 외부에 연락하지 않는다 |
| 거르기: 원문 없는 날짜·자격, 지난 공고, 반복 출처를 버린다 | 출처 없이 단정하지 않는다 |
| 번역하기: "왜 나에게"와 "지금 할 일"로 바꾼다 | 대표 대신 결정하지 않는다. 선택지와 근거를 준다 |
| 챙기기: 준비 중인 일과 마감을 추적하고 다시 알린다 | 모든 소식을 보내지 않는다. 하루 몇 개만 고른다 |
| 묻기: 판단에 모자란 정보를 되묻는다 | 대표의 정보를 외부에 보내지 않는다(검색 질의에 회사명·개인정보를 넣지 않는다) |

## 워크플로우

```text
[처음 한 번]  3분 설정 → 회사 모델 생성

[매일 아침]   1 관찰   회사 모델 → 테마별 질의 → Liner 웹 검색
              2 판단   출처 거르기 → 회사 모델에 대 보기(자격, 목표, 경쟁사)
              3 제안   우선순위로 고르기 → 아침 브리핑(가장 중요한 일 1 + 테마별)

[사용자]      4 반응   했어요 / 준비 시작 / 나중에 / 필요 없어요, 되묻기에 답
              5 기억   반응과 답 → 회사 모델 갱신
              6 추적   준비 중 체크리스트, 다가오는 마감 → 다음 브리핑에 반영
```

데모에서는 "매일 아침"을 "지금 찾기" 버튼으로 대신한다.

열린 결정: 2단계의 "왜 나에게"와 "할 일 한 줄"을 누가 쓰나(규칙·템플릿 / LLM API / Liner 요약·답변 기능). Cap 확인 후 HJ 결정. 구조도 참고.

## 기대효과

모두 가설이며 수치는 아직 없다. 테스터와 인터뷰로 확인한다.

- **놓치는 기회가 준다.** 자격이 맞는 공고를 마감 전에, 준비할 시간이 남았을 때 안다.
- **찾는 시간이 준다.** 여러 기관과 매체를 돌지 않아도 된다(통합공고 기준 111개 기관 508개 사업, PERSONAS S1).
- **알고 나서 행동까지 빨라진다.** 할 일 한 줄과 준비 목록이 시작 장벽을 낮춘다.
- **모르는 줄 몰랐던 일을 안다.** "우리 회사에 필요한 것"이 단계별로 챙길 일을 먼저 꺼낸다.
- **확장:** 회사 모델과 관찰·판단·제안 구조는 그대로 두고 테마만 바꾸면 다른 직무(영업: 고객사 동향, 연구: 논문·특허, 마케팅: 경쟁 캠페인)와 다른 조직으로 넓힐 수 있다.

## 평가 방법

테스터가 1~2명이고 기간이 짧다(11-21~23). 통계보다 행동 관찰과 인터뷰를 중심으로 한다. 목표치는 테스터 확정 후 정한다.

| 무엇을 | 어떻게 재나 | 무엇을 보여 주나 |
|---|---|---|
| 행동으로 이어지나 | 카드 중 "했어요"·"준비 시작" 비율 | 알림이 아니라 할 일이라는 주장 |
| 나에게 맞나 | "필요 없어요" 비율과 그 이유 | 회사 모델 기준 고르기가 통하는지 |
| 몰랐던 걸 알려 주나 | 카드마다 "몰랐어요 / 알고 있었어요" 한 번 묻기 | "모르는 줄 모르는" 문제를 푸는지 |
| 믿을 수 있나 | 카드 날짜·금액·자격을 원문과 대조한 일치율(소라가 표본 검수), 지난 공고 0건 | 출처 품질 기준 |
| 모델이 자라나 | 되묻기 응답률, 응답 후 카드의 "필요 없어요" 변화 | 쓰면서 자란다는 주장 |
| 계속 쓰고 싶나 | 사용 후 인터뷰: "미리내가 없어지면 아쉬운가", 실제로 시작한 일 사례 | 문제 정의의 증거 |
| 대회 기준 | Gemini 심사위원이 배점(문제 정의 30, 완성도 30, Liner 20, 확장성 20)으로 채점, GitHub 댓글 | 제출 전 약점 찾기 |
