# 미리내 MVP에서 보여 줄 것 (v0.3)

작성: 서비스PM Tony, 2026-11-17. 상태: 관문 2(데모 시나리오) 후보안, HJ 확인 전.

v0.3에서 방향을 바꿨다(DECISIONS 2026-11-17). v0.2(초기 창업자의 외부 변화 카드)는 11-13 인터뷰에서 "범위가 넓고 범용적이다, 차별성은 특정 업의 데이터·프로세스·반복 루프에서 나온다"는 지적을 받았다. 그래서 HJ가 직접 겪은 업무 하나로 좁혔다. v0.2는 git 이력에 있다.

## 한 줄

딜러를 통해 판매하는 제조사에 고객 문의가 들어오면, 미리내가 문의한 회사를 조사해 구매 의향을 가리고 맞는 딜러와 이유, 딜러에게 보낼 고객 요약까지 준비한다. 딜러가 기한 안에 응답하지 않으면 다른 딜러로 다시 배정하자고 먼저 제안한다. 사람은 애매한 건만 본다.

MVP가 증명할 것 하나: **문의가 들어와서 맞는 딜러에게 넘어가기까지의 시간이 며칠에서 몇 분으로 줄고, 사람이 직접 판단하는 건은 애매한 것만 남는다.**

## 문제 (HJ가 겪은 업무)

- 문의가 들어올 때마다 본사 세일즈가 한 건씩 전화해 구매 의향을 확인하고, 담당 딜러를 골라 연결한다.
- 문의가 몰리면 연결이 며칠씩 밀린다. 그사이 고객의 관심이 식는다.
- 이전에 산 딜러에게 바로 넘기면 빠를 것 같지만, 그 딜러의 대응이 느린 경우가 있다. 결국 건마다 사람이 판단한다.

[HJ] 겪은 장면 한두 개(사내 수치 없이, 예: "문의가 몰린 주에 연결이 3일 밀렸다")가 있으면 기획서와 영상의 근거가 된다. 회사명은 빼고 절차만 일반화해 쓴다.

**미리내가 줄이는 것:** 연결이 밀리는 이유는 본사 세일즈가 모든 문의에 전화를 건 뒤에야 딜러를 정하기 때문이다. 미리내는 공개 신호가 의향을 "대신 확인"한다고 주장하지 않는다. 문의 내용과 공개 신호로 근거 있는 우선순위를 매겨, 근거가 충분한 건은 본사 전화 없이 바로 딜러에게 넘기고(예산·시기 확인은 원래 딜러가 첫 통화에서 한다), 본사 전화는 근거가 모자란 "애매" 건에만 쓴다. 줄어드는 것은 본사가 거는 전화 수와 그 대기 시간이다. "낮음"은 안내 메일 초안으로 처리한다. [HJ: 실제로 본사 전화에서 확인하던 항목]

## 대상과 범위

- 사용자: 딜러망으로 파는 제조사(가상: 산업용 장비 제조사)의 본사 세일즈 담당자.
- 문의자: **기업 고객(B2B)만.** 조사는 회사 단위로 하고 개인을 검색하지 않는다(대회 규정: 개인정보 금지). [가정, HJ 확인 필요]
- 시연 데이터: 문의·거래 이력·딜러·응답 기록은 가상. 문의한 회사는 **공개된 실제 회사의 공개 정보**(증설, 채용, 수주 뉴스)로 Liner 검색을 실제로 돌리고, 화면에 "가상 문의"라고 밝힌다. [가정, HJ 확인 필요]

## 흐름

```text
① 문의 도착        문의함에 새 문의 (회사, 담당자 직함, 제품, 지역, 문의 내용)
② 회사 조사        Liner Search로 회사의 공개 신호를 찾는다 (증설, 신규 수주, 채용, 업종)
③ 구매 의향 판정    높음 / 애매 / 낮음 + 판정 이유 + 근거 링크
④ 딜러 추천        이전 거래, 담당 지역, 최근 응답 속도로 후보를 매기고 1순위와 이유를 보인다
⑤ 고객 요약        딜러에게 보낼 요약 초안 (회사 개요, 의향 근거, 문의 내용, 다음 행동)
⑥ 배정과 추적      "이 딜러에게 넘기기" → 응답 기한 카운트다운
⑦ 재배정 제안      기한 안에 응답 없으면 2순위 딜러로 다시 배정하자고 먼저 제안
```

사람이 보는 것: ③이 "애매"인 건과 ⑦의 재배정 승인만. 나머지는 미리내가 준비해 두고 사람은 확인만 한다.

## 판단 규칙 (MVP)

- 구매 의향: Liner Model API가 문의 내용과 검색된 공개 신호를 읽고 높음/애매/낮음과 이유를 낸다. 근거 링크가 없으면 "높음"을 주지 않는다(최대 "애매").
- 딜러 점수: 규칙 기반. 이전 거래 딜러 가산, 담당 지역 일치 가산, 최근 평균 응답 시간이 길수록 감점, 미응답 이력 감점. 점수와 각 항목을 화면에 보인다. 가중치는 가정값이다.
- 재배정: 배정 후 응답 기한(가정: 업무일 기준 4시간, 시연에서는 시계를 빨리 돌린다)이 지나면 2순위로 재배정 제안.
- **반복 루프:** 딜러의 응답 시간과 미응답이 기록에 쌓이고 다음 추천 점수에 바로 반영된다. 미응답 딜러는 다음 문의에서 순위가 내려간다. 이 데이터(딜러별 응답·성사 이력)는 제조사만 가진 것이고, 쌓일수록 배정이 정확해진다. 범용 도구와의 차별점이다.

### 실패 경로

| 상황 | 처리 |
|---|---|
| 검색 결과 없음 | "애매, 근거 없음"으로 사람 확인 대기열 |
| Liner API 실패·시간 초과 | 같음. 화면은 멈추지 않고 "조사 실패, 다시 시도" 표시 |
| 출처가 오래됨(1년 이상) | 근거로 쓰되 "오래된 출처" 표시, 최대 "애매" |
| 딜러 후보 없음(지역·제품 불일치) | 본사 세일즈 직접 처리로 표시 |

## Liner API 쓰는 지점 (배점 20)

| 지점 | API | 없으면 |
|---|---|---|
| 회사 공개 신호 찾기 | Search API | 판정 근거가 없다. 핵심 |
| 구매 의향 판정과 이유 | Model API | 규칙만으로는 문의 내용을 읽지 못한다 |
| 딜러용 고객 요약 | Model API | 세일즈가 다시 손으로 쓴다 |

왜 Liner인가: 판정의 근거가 곧 신뢰다. 미리내는 Liner 검색 결과(제목·URL·요약)를 판정 근거로 묶어 카드에 링크와 검색 시각으로 남기고, 근거 링크가 없으면 "높음"을 주지 않는다. 검색 → 근거 기반 판정 → 기록이 한 흐름이라 Liner가 빠지면 판정 자체가 성립하지 않는다. Liner에 인용 기반 답변 기능(Model API 등)이 실제로 있으면 판정 이유에 인용을 붙인다. [11-18 실호출에서 Search 응답 형태와 Model API 존재·엔드포인트를 확인. 현재 코드의 `/tools/search/web`은 title·url·description 목록을 준다(`docs/tech/LINER_API.md`)]

시연에서 실시간 결과와 미리 저장한 결과를 화면에 구분해 표시한다. 심사위원이 다른 키로 실행해 판정이 달라져도 흐름은 그대로 동작한다.
