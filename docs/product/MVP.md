## 한 줄

딜러망으로 파는 의료기기 제조사 Medicom(가상)에 온라인 리드가 들어오면, 미리내가 자사 기록과 리드의 소속 기관 공개 정보로 "진짜 고객인가"와 "어느 딜러가 믿을 만한가"를 판단해, 세일즈 담당자에게 근거가 붙은 결정 카드 하나로 빠르게 결정을 요청한다.

MVP가 증명할 것 하나: **무효 80%에 묻혀 있던 유효 리드 20%가 들어오자마자 맨 위로 올라와, 근거가 붙은 카드 하나로 믿을 만한 딜러에게 넘어간다.** 무효는 근거와 함께 묶어서 한 번에 확인하고, 전화는 애매한 건에만 건다.

## 문제 (HJ가 겪은 업무, 일반화)

1. 온라인으로 리드가 들어온다: 성, 이름, 이메일, 전화번호, 국가, 소속(회사·기관), 관심 상품, 메모.
2. 세일즈 리전 설정에 따라 담당자에게 배분된다. 조직 정보와 연동되지 않아 나라별 담당자를 가끔 손으로 맞춰야 한다.
3. 담당자는 리드에 대부분 전화로 연락해 진짜 고객인지, 구매 의향이 있는지 확인하고 지역 딜러에게 연결한다.

문제는 3번이다.

**공개 근거 — 늦게 연락하면 기회가 사라진다:**
- 미국 기업 2,241곳에 테스트 웹 문의를 보낸 감사에서 1시간 안에 응답한 곳은 37%, 아예 응답하지 않은 곳은 23%였고, 응답한 곳의 평균 응답 시간은 42시간이었다(Oldroyd·McElheran·Elkington, Harvard Business Review, 2011).
- 리드 125만 건 분석에서 1시간 안에 연락을 시도한 기업은 1시간 늦은 기업보다 의사결정자와 대화에 이를 가능성이 약 7배 높았다(같은 연구). 웹 리드 1.5만 건 분석에서는 5분 대신 30분 뒤에 전화하면 적격화 확률이 21배 낮아졌다(Oldroyd·InsideSales, 2007, 판매사 데이터).
- 한계: 미국 B2C·B2B 혼합의 10년 넘은 데이터이고, 측정한 것은 성약이 아니라 연락·적격화다.

**공개 근거 — 문의가 모두 기회는 아니다:** B2B SaaS 폼 제출 100만 건 이상에서 영업 전에 탈락시킨 비율은 18.7~37.7%, 대기업 대상은 71.2%였다(RevenueHero 2025 Inbound Benchmark, 판매사 자체 집계). 의료기기·제조업·딜러 판매 맥락의 무효율을 공개한 1차 자료는 찾지 못했다.

**시나리오 가정:** Medicom(가상)의 웹 문의를 월 약 200건, 그중 스팸·영업 제안·구직·학생·허위 정보 같은 비적격을 약 80%로 **가정**한다. 위 공개 범위의 상단보다 높은 값이라 근거로 주장하지 않고, MVP의 분류 결과로 검증할 가정으로 둔다. 담당자는 이 무효 물량에 전화를 거느라 정작 중요한 유효 리드에 연락할 타이밍을 놓친다(위 응답 속도 근거). 그리고 유효한 고객인지, 믿을 만한 딜러인지 두 판단이 모두 담당자 개인의 경험에 달려 있어, 사람마다 판단이 다르고 담당자가 바뀌면 경험이 사라진다.

즉 **소음 80%가 신호 20%를 묻는다.** 미리내의 첫 번째 일은 무효를 근거와 함께 빨리 걸러 유효 리드를 맨 위로 올리는 것이고, 두 번째 일은 그 유효 리드를 믿을 만한 딜러에게 바로 넘기는 것이다.

기존 도구와 다른 점: 일반 CRM의 리드 스코어링은 "얼마나 관심 있나"를 점수로 매기고 끝난다. 미리내는 딜러망을 가진 제조사의 두 판단, 즉 **진짜 기관 고객인가(외부 근거 링크로)와 어느 딜러에게 넘길 것인가(자사 딜러 응답 기록으로)** 를 한 카드에서 끝내고, 그 결정과 딜러 응답이 다시 기록이 된다. [researcher로 비교 대상 확인 예정]

기획서·영상에서 "월 약 200건, 약 80%"는 항상 "가정"으로 밝히고, 공개 근거는 출처와 한계를 함께 쓴다(researcher 조사 2026-11-18). 실제 회사의 수치로 쓰지 않는다. [HJ 확인 대기: 이 가정 표기로 쓰는 것, 열린 질문 6]

## 미리내가 하는 일

| 단계 | 미리내 |
|---|---|
| ① 리드 유입 | 가상 리드가 문의함에 들어온다 |
| ② 담당자 확인 | 리드 국가에 담당자가 없거나 어긋나면 "담당자 없음"으로 먼저 알린다 (보조) |
| ③ 유효 고객 판단 | **소속 기관 조사(Liner Search):** 기관이 실재하나, 소재지가 리드 국가와 맞나, 공식 도메인이 이메일과 맞나(업종은 참고 표시). **자사 기록:** 같은 이메일·전화·기관의 과거 리드와 결과, 구매 이력, 스팸 패턴(무료 메일 + 소속 없음 등), 메모 내용. 결과: 유효 / 애매 / 국가 확인 / 제휴 확인 / 무효 + 근거 |
| ④ 딜러 판단 | 리드 국가를 맡은 딜러별 **최근 90일 거래 이력**: 본사가 넘긴 리드와 그 결과(deal / no deal / 진행 중), 미응답 이력, 이 기관과의 거래로 순위와 이유 |
| ⑤ 결정 요청 | 결정 카드 하나: "이 리드를 ○○ 딜러에게 넘길까요?" + 근거 3개. **승인 / 딜러 변경 / 전화 필요 / 무효 처리** (HJ 확인 2026-11-18) |
| ⑥ 추적·재배정 | 넘긴 뒤 딜러가 기한 안에 응답하지 않으면 다른 딜러로 재배정 제안 (11-24 범위 밖. 미응답 기록과 순위 반영만 한다, "11-24 범위") |
| ⑦ 기록 반영 | 담당자의 결정, 딜러 응답, 결과가 기록에 쌓여 다음 ③④ 판단에 바로 쓰인다 |

문의함은 판정별로 다섯 묶음이다: **유효(맨 위, 결정 카드) / 애매(전화 필요 목록) / 국가 확인(자동 메일 후 회신 대기) / 제휴 확인(자동 메일 후 회신 대기) / 무효(일괄 확인 목록).** 무효 목록은 한 줄씩 무효 이유(소속 없음, 기관을 찾지 못함, 사칭 의심, 영업·학생·구직 등)를 보이고, 담당자는 훑어본 뒤 "일괄 무효 처리"를 한 번 누르거나 잘못 걸린 건만 꺼낸다. 무효 리드 하나하나에 결정 카드를 띄우지 않는다. 일괄 무효 처리에는 무효 묶음만 들어가고 확인 대기 건은 섞이지 않는다. 업종만으로 무효가 되는 일은 없다.

**판정과 업무 상태는 따로 둔다.** 판정은 위 다섯 가지, 업무 상태는 새 리드 / 결정 대기 / 회신 대기 / 담당자 확인 대기 / 딜러 배정 / 연결 완료 / 무효 처리다. 국가·제휴 확인의 회신은 담당자가 화면에 입력하는 수동 이벤트로 받고(실제 메일 수신 연동은 하지 않는다), 입력하면 그 내용으로 다시 판정한다.

담당자가 하는 일: 유효 카드 승인, 애매 건 전화, 확인 대기 건 회신 입력, 무효 목록 일괄 확인.

## 판단 규칙 (MVP)

- 유효 고객은 두 겹으로 본다.
  - **실재와 소재지:** 소속 기관이 공개 정보로 확인되나, 소재지가 리드 국가와 맞나. 확인하지 못하면 "유효"를 주지 않는다(최대 "애매").
  - **업종은 판정에 쓰지 않는 참고 사항이다(HJ 결정 2026-11-18).** 카드에 보여 주기만 한다.
  - **메모 의도:** 구매·검토면 유효 후보, 제휴·협업 제안이면 "제휴 확인"(제휴 세부 사항을 요청하는 메일 자동 발송 후 회신 대기), 우리에게 팔려는 영업·과제·채용이면 무효, 알 수 없으면 애매. 표는 `DEMO_DATA.md` "업종 기준". 기본은 언어별(한·영·일) 키워드 규칙이고, 규칙으로 정하지 못하면 애매(전화)로 보낸다.
  - **도메인 대조:** 기관 공식 도메인(또는 검증된 별칭)과 리드 이메일 도메인을 비교한다. 일치하면 강한 근거, 무료 메일이면 애매. 공식 도메인·별칭과 다를 때는 둘로 나눈다.
    - **사칭 의심(무효):** 이메일 도메인이 기관명(영문 표기 포함)의 단어를 담은 닮은꼴인데 공식 도메인·별칭과 다르다(예: `asan-medical.test`, `clevelandclinic-mail.test`), 또는 검색으로 확인된 다른 기관의 공식 도메인이다.
    - **도메인 확인 못 함(애매):** 그 밖에 소유 관계를 확인하지 못한 도메인(등록되지 않은 별칭일 수 있다. 예: 별칭이 없을 때의 `ccf.org`, `yuhs.ac`).
- **판정 순서 (조건이 겹칠 때, 위가 먼저):** ① 명백한 무효(소속 없음·스팸, 기관을 찾지 못함, 사칭 의심, 영업·학생·구직) → ② 기관·도메인 불확실(무료 메일, 도메인 확인 못 함, 소재지 불명, 외부 확인 실패)은 애매 → ③ 소재지가 한 나라로 분명하고 리드 국가와 다르면 국가 확인 → ④ 제휴·협업 제안이면 제휴 확인 → ⑤ 구매·검토면 유효, 의도를 모르면 애매. 국가 확인 중인 건에 제휴 상세 요청 메일을 겹쳐 보내지 않는다(회신으로 국가가 정해진 뒤 다시 판정).
- Search 결과만으로 판정하는 규칙 (Model API가 없어도 동작해야 한다):
  - 질의는 리드당 2회: "기관명 + 국가"(실재·소재지·공식 도메인), "기관명 + 업종 키워드"(병원·치과·의원·연구소 등). 같은 기관·국가 질의는 캐시해 다시 부르지 않는다.
  - **공식 도메인:** 기관 공식 페이지로 보이는 결과(제목·URL에 기관명 또는 영문 표기가 있고, 위키·뉴스·SNS·리뷰·디렉터리 도메인이 아닌 것)의 도메인만 인정한다. 제3자 페이지에 나온 도메인은 이메일 일치 근거로 쓰지 않는다. 고르지 못하면 "도메인 확인 못 함"으로 애매.
  - **하위 도메인:** 이메일 도메인이 공식 도메인과 같거나, 점(.) 경계로 끝나는 하위 도메인이면 일치(`h.u-tokyo.ac.jp`는 `u-tokyo.ac.jp`와 일치, `evil-u-tokyo.ac.jp`는 불일치).
  - **도메인 별칭:** 사이트 도메인과 이메일 도메인이 다른 기관이 많다(예: 사이트 clevelandclinic.org, 메일 ccf.org). 설정의 "기관 도메인 별칭"(기관명 → 알려진 이메일 도메인, 공개 출처 링크 포함)에 있으면 일치로 본다. 시연 초기값에는 `DEMO_DATA.md` "출처"로 확인한 별칭을 넣는다(담당자가 이미 한 번 등록해 둔 상태). 별칭이 없고 공식 도메인과도 다르면 위 "도메인 대조"의 두 갈래(닮은꼴·타기관이면 사칭 의심 무효, 그 밖에는 도메인 확인 못 함 애매)를 따른다.
  - 업종: 결과 제목·요약의 업종 키워드를 주요 고객 업종 목록과 대조한다(참고 표시만).
  - **소재지:** 요약·제목 속 국가·도시명으로 본다. 국가 도메인(.kr 등)만으로는 정하지 않는다. 한 나라로 분명하면 리드 국가와 비교하고, 근거가 없거나 여러 나라가 나오면(다국적 기관) 소재지 불명으로 애매.
  - **기관을 찾지 못함:** 검색이 정상 응답했는데 두 질의 모두 기관명과 맞는 결과가 없으면 "공개 정보에서 기관을 찾지 못함"으로 무효(HJ 결정: 실재하지 않으면 무효). 무효 목록에 이유와 함께 나오고 담당자가 꺼낼 수 있다. 검색 실패·시간 초과는 부재의 근거가 아니므로 애매("외부 확인 실패, 다시 시도"). 정답셋의 "가상 기관" 표시는 판정 엔진 입력으로 주지 않는다.
  - 이유 문장: 규칙 결과를 템플릿 문장으로 만든다("소속 기관이 확인되고, 이메일 도메인이 공식 도메인과 같아요"). Model API는 #26에서 쓸 수 있다고 확인된 뒤 선택한다.
- 구매 의향: 메모, 관심 상품, 같은 기관의 과거 리드·구매 이력으로 높음/보통/불명을 낸다(규칙 기본, Model API는 확인 뒤 선택). 메모로 의향을 알 수 없으면 "불명"이고, 이 경우 카드는 "전화 필요"를 추천한다. **미리내는 모든 전화를 없앤다고 주장하지 않는다. 근거가 충분한 건은 전화 없이 넘기고, 전화가 필요한 건과 그 이유를 가려 준다.**
- 사람은 검색하지 않는다. 개인 정보는 자사 기록 대조에만 쓴다.
- 소속 기관 소재지와 리드 국가가 다르면 무효로 버리지 않고, 리드에게 국가 확인 메일을 자동으로 보내고 "국가 확인 대기"로 둔다. 회신으로 국가가 정해지면 그 국가 기준으로 다시 판정·배분한다(지금 업무는 리드 국가로 담당자에게 넘긴다).
- 딜러 순위: 규칙 기반, **최근 90일 안에 본사가 넘긴 리드의 결과**로 본다(HJ 제안 2026-11-17).
  - 전달 결과는 deal / no deal / 진행 중 / 미응답(기한 안에 응답 없음) 넷 중 하나다.
  - **전환율 = deal ÷ (deal + no deal).** 진행 중과 미응답은 분모에서 빼고 건수만 따로 보인다. 카드 표기 예: "전달 8 · deal 3 / 종료 7 · 진행 중 1 · 미응답 0".
  - **이력 적음:** 최근 90일 전달 총수가 3건 미만이면 "이력 적음"으로 표시하고 전환율로 순위를 매기지 않는다.
  - **점수 = 전환율 − 미응답 1건당 0.1 + 이 기관과 이전 거래 0.1** (기본값, 정책 파일에서 변경). 같은 점수면 deal 건수가 많은 딜러, 그래도 같으면 이름순. 리드의 관심 상품을 취급하지 않는 딜러는 후보에서 뺀다(시연 딜러는 모두 세 상품을 취급).
  - no deal은 이유를 나누지 않고 모두 센다. 고객의 구매 보류도 딜러가 제때 연락했는지, 협상을 잘못했는지 가리기 어렵기 때문이다(HJ 결정 2026-11-17).
  - 점수와 항목을 카드에 보인다.
  - 리드 국가에 이력 적은 신규 딜러만 있으면 바로 넘기지 않고 **그 지역 세일즈 담당자에게 확인 요청**을 보낸다(HJ 결정 2026-11-18). 담당자가 확인하기 전에는 자동 전달하지 않는다.
  - 비활성 딜러는 새 추천에서 뺀다. 기준값을 바꾸면 아직 승인하지 않은 추천만 다시 계산하고, 이미 승인한 배정과 기록은 그대로 둔다.
- 세일즈 담당자는 지역 단위 5명이다: 북미(미국·캐나다), 라틴아메리카(멕시코 포함), APAC, EU, MEA·아프리카(HJ 결정 2026-11-18). 나라 → 지역 매핑은 정책 파일에서 바꾸고, 매핑에 없는 나라는 "지역 미지정" 알림(흐름 ②).
- **기준값은 서비스 정책이다.** 집계 기간(기본 90일), 이력 적음 기준(기본 3건 미만), 딜러 응답 기한, 가중치는 임의로 정한 기본값이며 회사 정책에 맞게 바꿀 수 있다. 11-24 범위에서는 **정책 파일**로 바꾸고, 설정 화면은 범위 밖이다. 카드와 기획서에 "기본값, 정책으로 변경 가능"이라고 밝힌다.
- 재배정(11-24 범위 밖): 응답 기한(가정: 업무일 기준 1일, 시간대 Asia/Seoul, 주말 제외)이 지나면 다음 순위 딜러로 재배정 제안.
- 반복 루프: 결정·응답·결과가 기록에 쌓이고 다음 판단에 바로 반영된다. 11-24 범위에서는 담당자가 딜러 결과(deal / no deal / 미응답)를 화면에 입력하면 기록에 쌓이고, 다음 리드의 딜러 순위가 그 기록으로 다시 계산되는 것까지 보인다(장면 6). 이 기록은 제조사만 가진 것이라 범용 도구가 대신할 수 없다. 정확도가 오르는지는 MVP에서 증명하지 않는다.
- **저장:** 단일 사용자 로컬 저장. 새로고침해도 상태가 남고, "시연 초기화"로 처음 상태로 돌린다. 같은 승인을 두 번 눌러도 한 번만 반영된다.

## Liner API 쓰는 지점 (배점 20)

| 지점 | API | 없으면 |
|---|---|---|
| 소속 기관 실재·업종·소재지 확인 | Search API | 유효 판정의 외부 근거가 없다. 핵심 |
| 기관 공식 도메인 ↔ 리드 이메일 대조 | Search API 결과 | 사칭·무관 리드를 거르지 못한다 |
| 유효 판정 이유, 딜러 추천 이유, 다국어 메모 의도 | Model API (선택) | 규칙 + 검색 요약 + 템플릿으로 쓴다(기본 경로) |
| 딜러에게 보낼 리드 요약 | Model API (선택) | 템플릿으로 쓴다(기본 경로) |

왜 Liner인가: 판정의 근거가 곧 신뢰다. 미리내는 Liner 검색 결과(제목·URL·요약)를 판정 근거로 묶어 카드에 링크와 검색 시각으로 남기고, 소속을 공개 정보로 확인하지 못하면 "유효"를 주지 않는다. Liner가 빠지면 외부 근거가 없어 판정이 담당자 경험으로 되돌아간다.

확인 상태(#26, 11-18): 인증과 Search 단일 검색(서울대학교병원, 공식 도메인 포함 3건, title·url·description)은 성공. 5기관 × 2질의 품질 평가와 Model API 존재·엔드포인트는 아직이다. 5기관 중 실재·업종·소재지·공식 도메인 네 항목이 모두 확인된 기관이 3곳 이상이면 실시간 조사로 시연하고, 미달이면 실시간 Search는 그대로 두고 출처·시각을 밝힌 저장 결과로 시연한다. Model API는 확인되기 전까지 쓰지 않는 것으로 계획하고, Search를 핵심으로 둔다.

시연에서 실시간 결과와 미리 저장한 결과를 화면에 구분해 표시한다. 심사위원이 다른 키로 실행해 판정이 달라져도 흐름은 그대로 동작한다.

PC 웹 하나: 문의함(다섯 묶음, 무효는 이유와 함께 일괄 처리), 리드 상세(소속 조사, 기록 대조, 판정, 딜러 추천, 결정 카드, 요약, 회신·딜러 결과 입력). 모바일은 만들지 않는다. 딜러 현황 화면과 설정 화면은 11-24 범위 밖이다.

## 설정

모두 서비스 정책이라 회사에 맞게 바꾼다. 11-24 범위에서는 아래 값을 **정책 파일**(저장소의 기본값 파일)로 두고 화면 편집은 하지 않는다. 설정 화면을 넣게 되면 기본값을 보여 주고 "기본값으로 되돌리기"를 둔다.

| 설정 | 내용 | 기본값 |
|---|---|---|
| 딜러 관리 | 딜러 추가, 정보 수정, 비활성화(삭제 대신. 과거 전달 내역은 남긴다) | 시연 딜러 7곳 |
| 판정 기준 | 집계 기간, 이력 적음 기준, 딜러 응답 기한, 점수 가중치 | 90일, 전달 3건 미만, 업무일 1일, 미응답 −0.1·이전 거래 +0.1 |
| 주요 고객 업종 | 상품별 업종 목록. 판정에는 쓰지 않고 카드 참고 표시용 | 병원·의원, 치과, 연구소, 대학 연구실, 제약·바이오, 의료기기 유통 |

**딜러 추가**: 이름, 맡는 나라(여러 개 가능), 취급 상품, 연락 메일(테스트 환경에서는 테스트 수신함으로 바뀐다)을 넣는다. 새 딜러는 전달 내역이 없으므로 "신규, 이력 적음"으로 표시되고, 전환율로 순위를 매기지 않는다. 그 나라에 이력 적은 딜러만 있으면 바로 넘기지 않고 지역 담당자에게 확인 요청을 보낸다(판단 규칙과 같다). 다른 딜러가 있으면 담당자가 "딜러 변경"으로 신규 딜러를 직접 고를 수 있다. 전달 수가 기준 건수(기본 3건) 이상이 되면 자동으로 전환율 순위에 들어간다.

## 테스트 환경의 메일

- 가상 리드의 이메일은 모두 페이크다. 인물 이름(앞부분)은 가상이고, 도메인 대조를 위해 실제 기관 도메인을 쓰는 리드도 있다. 그래서 **테스트 환경에서는 리드 주소로 실제 발송하지 않는다.**
- 제품에서 나가는 메일은 다섯 가지다: 딜러용 리드 요약(승인·재배정 때), 리드에게 가는 국가 확인 메일(소재지와 리드 국가가 다를 때), 리드에게 가는 제휴 상세 요청 메일(제휴 제안일 때), 지역 담당자 확인 요청(신규 딜러만 있을 때), 운영 알림(HJ 결정 2026-11-18). 테스트 환경에서는 수신자가 누구든 모두 **QA·운영 테스트 수신함 한 곳**으로 바꿔 보내고, 본문 첫 줄에 원래 수신자 종류를 적는다(아래).
- 발신은 HJ가 지정한 발신 전용 Gmail 계정(SMTP + 앱 비밀번호)이다. 주소는 환경 변수(`TEST_MAIL_TO`, `.env.local`)에 두고 저장소·Issue·문서에 적지 않는다(저장소는 제출 때 공개될 수 있다).
- 코드는 수신 주소를 이 한 곳만 허용한다. 템플릿을 채운 뒤 **마지막 전송 단계에서 to·cc·bcc 전부**를 검사하고, `TEST_MAIL_TO` 외의 주소가 하나라도 있으면 막고 기록만 남긴다. 본문 첫 줄은 "가상 리드 테스트 메일, 원래 수신자: 딜러/리드/지역 담당자/운영"이고 실제 주소는 쓰지 않는다.
- 같은 이벤트(이벤트 ID)로는 한 번만 보낸다. 실패하면 상태를 남겨 다시 시도할 수 있게 하고, 시간 초과로 보냈는지 모를 때는 자동으로 다시 보내지 않고 "전송 불명"으로 둬 확인 뒤 처리한다.
- 영상에서는 승인 뒤 테스트 수신함에 딜러용 요약 메일이 도착하는 장면을 보일 수 있다.
