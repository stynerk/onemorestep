# 미리내 MVP에서 보여 줄 것 (v0.4)

작성: 서비스PM Tony, 2026-11-17. 상태: 관문 2(데모 시나리오) 후보안, HJ 확인 전.

v0.3에서 방향을 바꿨다(DECISIONS 2026-11-17). v0.2(초기 창업자의 외부 변화 카드)는 11-13 인터뷰에서 "범위가 넓고 범용적이다, 차별성은 특정 업의 데이터·프로세스·반복 루프에서 나온다"는 지적을 받아, HJ가 직접 겪은 업무 하나로 좁혔다. v0.4는 HJ가 실제 업무 흐름을 설명해 준 내용을 반영했다(회사명과 사내 수치는 쓰지 않고 일반화). 이전 판은 git 이력에 있다.

## 한 줄

딜러망으로 파는 의료기기 제조사 Medicom(가상)에 온라인 리드가 들어오면, 미리내가 자사 기록과 리드의 소속 기관 공개 정보로 "진짜 고객인가"와 "어느 딜러가 믿을 만한가"를 판단해, 세일즈 담당자에게 근거가 붙은 결정 카드 하나로 빠르게 결정을 요청한다.

MVP가 증명할 것 하나: **무효 80%에 묻혀 있던 유효 리드 20%가 들어오자마자 맨 위로 올라와, 근거가 붙은 카드 하나로 믿을 만한 딜러에게 넘어간다.** 무효는 근거와 함께 묶어서 한 번에 확인하고, 전화는 애매한 건에만 건다.

## 문제 (HJ가 겪은 업무, 일반화)

1. 온라인으로 리드가 들어온다: 성, 이름, 이메일, 전화번호, 국가, 소속(회사·기관), 관심 상품, 메모.
2. 세일즈 리전 설정에 따라 담당자에게 배분된다. 조직 정보와 연동되지 않아 나라별 담당자를 가끔 손으로 맞춰야 한다.
3. 담당자는 리드에 대부분 전화로 연락해 진짜 고객인지, 구매 의향이 있는지 확인하고 지역 딜러에게 연결한다.

문제는 3번이다. **규모 (HJ 경험, 대략):** 리드는 한 달에 약 200건, 그중 약 80%가 무효(disqualified)다. 담당자는 이 무효 물량에 전화를 거느라 정작 중요한 유효 리드 약 20%에 연락할 타이밍을 놓친다. 그리고 유효한 고객인지, 믿을 만한 딜러인지 두 판단이 모두 담당자 개인의 경험에 달려 있어, 사람마다 판단이 다르고 담당자가 바뀌면 경험이 사라진다.

즉 **소음 80%가 신호 20%를 묻는다.** 미리내의 첫 번째 일은 무효를 근거와 함께 빨리 걸러 유효 리드를 맨 위로 올리는 것이고, 두 번째 일은 그 유효 리드를 믿을 만한 딜러에게 바로 넘기는 것이다.

기존 도구와 다른 점: 일반 CRM의 리드 스코어링은 "얼마나 관심 있나"를 점수로 매기고 끝난다. 미리내는 딜러망을 가진 제조사의 두 판단, 즉 **진짜 기관 고객인가(외부 근거 링크로)와 어느 딜러에게 넘길 것인가(자사 딜러 응답 기록으로)** 를 한 카드에서 끝내고, 그 결정과 딜러 응답이 다시 기록이 된다. [researcher로 비교 대상 확인 예정]

규모 수치는 HJ가 아는 대략값이며 기획서·영상에는 "약", "경험상"으로만 쓴다. [HJ: 사내 수치에 해당하지 않는지 최종 확인]

## 미리내가 하는 일

| 단계 | 미리내 |
|---|---|
| ① 리드 유입 | 가상 리드가 문의함에 들어온다 |
| ② 담당자 확인 | 리드 국가에 담당자가 없거나 어긋나면 "담당자 없음"으로 먼저 알린다 (보조) |
| ③ 유효 고객 판단 | **소속 기관 조사(Liner Search):** 기관이 실재하나, 업종이 관심 상품과 맞나, 소재지가 리드 국가와 맞나. **자사 기록:** 같은 이메일·전화·기관의 과거 리드와 결과, 구매 이력, 스팸 패턴(무료 메일 + 소속 없음 등), 메모 내용. 결과: 유효 / 애매 / 무효 + 근거 |
| ④ 딜러 판단 | 리드 국가를 맡은 딜러별 **최근 90일 거래 이력**: 본사가 넘긴 리드와 그 결과(deal / no deal / 진행 중), 미응답 이력, 이 기관과의 거래로 순위와 이유 |
| ⑤ 결정 요청 | 결정 카드 하나: "이 리드를 ○○ 딜러에게 넘길까요?" + 근거 3개. **승인 / 딜러 변경 / 전화 필요 / 무효 처리** [HJ 확인: 실제 결정과 맞는지] |
| ⑥ 추적·재배정 | 넘긴 뒤 딜러가 기한 안에 응답하지 않으면 다른 딜러로 재배정 제안 |
| ⑦ 기록 반영 | 담당자의 결정, 딜러 응답, 결과가 기록에 쌓여 다음 ③④ 판단에 바로 쓰인다 |

문의함은 판정별로 나뉜다: **유효(맨 위, 결정 카드) / 애매(전화 필요 목록) / 무효(일괄 확인 목록).** 무효 목록은 한 줄씩 무효 이유(소속 없음, 업종 불일치, 사칭 의심 등)를 보이고, 담당자는 훑어본 뒤 "일괄 무효 처리"를 한 번 누르거나 잘못 걸린 건만 꺼낸다. 무효 리드 하나하나에 결정 카드를 띄우지 않는다.

담당자가 하는 일: 유효 카드 승인, 애매 건 전화, 무효 목록 일괄 확인.

## 판단 규칙 (MVP)

- 유효 고객은 두 겹으로 본다.
  - **실재와 소재지:** 소속 기관이 공개 정보로 확인되나, 소재지가 리드 국가와 맞나. 확인하지 못하면 "유효"를 주지 않는다(최대 "애매").
  - **업종은 참고 신호다(HJ 결정 2026-11-18: 의료로 제한하지 않는다).** 주요 고객 업종(설정에서 상품별로 바꿈)이고 메모에 구매 의도가 있으면 유효 후보, 그 밖의 업종이라도 구매 의도가 있으면 애매(전화 확인), 업종과 관계없이 영업·제휴·입점·과제·채용 메모는 무효. 표는 `DEMO_DATA.md` "업종 기준".
  - **도메인 대조:** Liner 검색 결과에서 나온 기관 공식 도메인과 리드 이메일 도메인을 비교한다. 일치하면 강한 근거, 무료 메일이면 "애매" 쪽, 다른 기관 도메인이면 사칭 의심으로 "무효" 후보.
- Search 결과만으로 판정하는 규칙 (Model API가 없어도 동작해야 한다):
  - 질의는 리드당 2회: "기관명 + 국가"(실재·소재지·공식 도메인), "기관명 + 업종 키워드"(병원·치과·의원·연구소 등).
  - 공식 도메인: 결과 URL 중 기관명(영문 표기 포함)과 도메인이 가장 닮은 것을 고르고, 위키·뉴스·SNS 도메인은 제외한다. 고르지 못하면 "도메인 확인 못 함".
  - 업종: 결과 제목·요약의 업종 키워드를 주요 고객 업종 목록과 대조한다(참고 신호).
  - 도메인 별칭: 사이트 도메인과 이메일 도메인이 다른 기관이 많다(예: 사이트 clevelandclinic.org, 메일 ccf.org). 검색 결과에 나온 모든 도메인을 후보로 보고, 이메일 도메인이 그중 하나이거나 하위 도메인이면 일치. 못 찾으면 "도메인 확인 못 함"으로 애매. 담당자가 설정의 "기관 도메인 별칭"에 한 번 등록하면 다음부터 맞게 판정한다.
  - 소재지: 결과의 국가 도메인(.kr 등)이나 요약 속 국가·도시명이 리드 국가와 맞는지.
  - 이유 문장: Model API가 있으면 모델이 쓰고, 없으면 규칙 결과를 템플릿 문장으로 만든다("소속 기관이 확인되고, 이메일 도메인이 공식 도메인과 같아요").
- 구매 의향: 메모, 관심 상품, 같은 기관의 과거 리드·구매 이력으로 Liner Model API가 높음/보통/불명을 낸다. 메모로 의향을 알 수 없으면 "불명"이고, 이 경우 카드는 "전화 필요"를 추천한다. **미리내는 모든 전화를 없앤다고 주장하지 않는다. 근거가 충분한 건은 전화 없이 넘기고, 전화가 필요한 건과 그 이유를 가려 준다.**
- 사람은 검색하지 않는다. 개인 정보는 자사 기록 대조에만 쓴다.
- 기관이 실재하지 않으면 무효다(HJ 결정 2026-11-18).
- 소속 기관 소재지와 리드 국가가 다르면 무효로 버리지 않고, 리드에게 국가 확인 메일을 자동으로 보내고 "국가 확인 대기"로 둔다. 회신으로 국가가 정해지면 그 국가 기준으로 다시 판정·배분한다(지금 업무는 리드 국가로 담당자에게 넘긴다).
- 딜러 순위: 규칙 기반, **최근 90일 안에 본사가 넘긴 리드의 결과**로 본다(HJ 제안 2026-11-17).
  - deal 비율은 "deal 3 / 넘긴 8"처럼 건수로 보인다. 넘긴 건이 3건 미만이면 "이력 적음"으로 표시하고 비율로 순위를 매기지 않는다.
  - 결과가 아직 없는 "진행 중"은 비율 계산에서 빼고 건수만 보인다.
  - 미응답(기한 안에 응답 없음)은 감점, 이 기관과의 이전 거래는 가산.
  - no deal은 이유를 나누지 않고 모두 센다. 고객의 구매 보류도 딜러가 제때 연락했는지, 협상을 잘못했는지 가리기 어렵기 때문이다(HJ 결정 2026-11-17).
  - 점수와 항목을 카드에 보인다.
- **기준값은 서비스 정책이다.** 집계 기간(기본 90일), 이력 적음 기준(기본 3건 미만), 딜러 응답 기한, 가중치는 임의로 정한 기본값이며 회사 정책에 맞게 바꿀 수 있다. 화면의 **설정**에서 바꾸고, 바꾸면 딜러 순위가 바로 다시 계산된다. 카드와 기획서에 "기본값, 설정에서 변경 가능"이라고 밝힌다.
- 재배정: 응답 기한(가정: 업무일 기준 1일, 시연에서는 시계를 빨리 돌린다)이 지나면 다음 순위 딜러로 재배정 제안.
- 반복 루프: 결정·응답·결과가 기록에 쌓이고 다음 판단에 바로 반영된다(장면 6-1: 미응답 딜러의 순위가 내려감). 이 기록은 제조사만 가진 것이라 범용 도구가 대신할 수 없다. 정확도가 오르는지는 MVP에서 증명하지 않는다.

## Liner API 쓰는 지점 (배점 20)

| 지점 | API | 없으면 |
|---|---|---|
| 소속 기관 실재·업종·소재지 확인 | Search API | 유효 판정의 외부 근거가 없다. 핵심 |
| 기관 공식 도메인 ↔ 리드 이메일 대조 | Search API 결과 | 사칭·무관 리드를 거르지 못한다 |
| 유효 판정과 이유, 딜러 추천 이유 | Model API | 기록과 메모를 읽고 이유를 쓰지 못한다 |
| 딜러에게 보낼 리드 요약 | Model API | 담당자가 다시 손으로 쓴다 |

왜 Liner인가: 판정의 근거가 곧 신뢰다. 미리내는 Liner 검색 결과(제목·URL·요약)를 판정 근거로 묶어 카드에 링크와 검색 시각으로 남기고, 소속을 공개 정보로 확인하지 못하면 "유효"를 주지 않는다. Liner가 빠지면 외부 근거가 없어 판정이 담당자 경험으로 되돌아간다. [확인 예정(11-18 오전): Search 응답 형태와 Model API 존재·엔드포인트. 현재 코드의 `/tools/search/web`은 title·url·description 목록을 준다(`docs/tech/LINER_API.md`). Model API가 없으면 판정 이유는 규칙 + 검색 요약으로 만들고, Search를 유일한 핵심으로 둔다]

시연에서 실시간 결과와 미리 저장한 결과를 화면에 구분해 표시한다. 심사위원이 다른 키로 실행해 판정이 달라져도 흐름은 그대로 동작한다.

## 시연 데이터

상세와 정답셋은 [`DEMO_DATA.md`](DEMO_DATA.md)가 정본이다.

- 리드 30건(월 약 200건 규모의 며칠 치), 11개 나라, 실제 공개 기관 23건 + 가상 기관·소속 없음 7건. 인물과 이메일 앞부분은 가상. 화면에 "가상 리드, 공개 기관 정보만"이라고 밝힌다.
- 딜러 7곳, 국가 단위(대한민국 2, 일본 1, 미국 2, 독일 1, 싱가포르 1 신규). 딜러 없는 나라도 있다.
- 구성: 유효 7, 애매 4, 국가 확인 3, 무효 16. "검색 결과가 있으면 유효"만으로는 맞힐 수 없게 섞었다(실제 기관이지만 제휴 제안·학생·사칭, 비의료 기업이지만 구매 의도). 유효 중 1건은 늦게 들어와 묻힌 "놓칠 뻔한 리드"다.
- 정답셋: HJ가 실무자 눈으로 30건에 정답(유효/애매/무효, 넘길 딜러)을 먼저 매긴다. 영상은 미리내 판정과 정답의 일치율을 보여 주고, 틀린 건도 그대로 보인다.

## 설정

모두 서비스 정책이라 회사에 맞게 바꾼다. 기본값을 보여 주고 "기본값으로 되돌리기"를 둔다.

| 설정 | 내용 | 기본값 |
|---|---|---|
| 딜러 관리 | 딜러 추가, 정보 수정, 비활성화(삭제 대신. 과거 전달 내역은 남긴다) | 시연 딜러 7곳 |
| 판정 기준 | 집계 기간, 이력 적음 기준, 딜러 응답 기한, 점수 가중치 | 90일, 3건 미만, 업무일 1일 |
| 주요 고객 업종 | 상품별 업종 목록 | 병원·의원, 치과, 연구소, 대학 연구실, 제약·바이오, 의료기기 유통 |
| 기관 도메인 별칭 | 기관명 → 알려진 이메일 도메인 | 비어 있음 |

**딜러 추가**: 설정 → 딜러 관리 → "딜러 추가"에서 이름, 맡는 나라(여러 개 가능), 취급 상품, 연락 메일(테스트 환경에서는 테스트 수신함으로 바뀐다)을 넣는다. 새 딜러는 전달 내역이 없으므로 "신규, 이력 적음"으로 표시되고, deal 비율로 순위를 매기지 않는다. 그 나라에 다른 딜러가 없으면 신규 딜러를 추천하되 표시를 붙이고, 있으면 담당자가 "딜러 변경"으로 직접 고를 수 있다. 넘긴 리드가 기준 건수(기본 3건)를 넘으면 자동으로 비율 순위에 들어간다.

## 테스트 환경의 메일

- 가상 리드의 이메일은 모두 페이크다. 인물 이름(앞부분)은 가상이고, 도메인 대조를 위해 실제 기관 도메인을 쓰는 리드도 있다. 그래서 **테스트 환경에서는 리드 주소로 실제 발송하지 않는다.**
- 제품에서 나가는 메일은 세 가지다: 딜러용 리드 요약(승인·재배정 때), 리드에게 가는 국가 확인 메일(소재지와 리드 국가가 다를 때, HJ 결정 2026-11-18), 운영 알림. 테스트 환경에서는 수신자가 누구든 모두 **QA·운영 테스트 수신함 한 곳**으로 바꿔 보내고, 본문 첫 줄에 원래 수신자 종류(딜러/리드)를 적는다.
- 발신은 HJ가 지정한 발신 전용 Gmail 계정(SMTP + 앱 비밀번호)이다. 주소는 환경 변수(`TEST_MAIL_TO`, `.env.local`)에 두고 저장소·Issue·문서에 적지 않는다(저장소는 제출 때 공개될 수 있다).
- 코드는 수신 주소를 이 한 곳만 허용한다. 다른 주소로 보내려 하면 막고 기록만 남긴다.
- 영상에서는 승인 뒤 테스트 수신함에 딜러용 요약 메일이 도착하는 장면을 보일 수 있다.
