# 미리내 화면 디자인 개선안 (frontend-design 방식)

작성: 서비스PM Tony, 2026-11-24. 근거: 데모 영상 v3 캡처(1440×900), HJ 피드백("화면 디자인이 많이 아쉽다"). 구현: Issue #113.

## 1. 주제에서 출발

- **무엇:** 의료기기 제조사 본사 세일즈 데스크의 리드 **트리아지(분류)와 전달(라우팅)** 화면.
- **누가:** 하루에 수십 건을 처리하는 세일즈·마케팅 실무자. 심사위원은 영상과 공개 주소로 처음 본다.
- **화면의 첫 번째 일:** "이 리드를 누구에게 넘길지 지금 결정한다"를 한눈에. 근거는 그 바로 아래.
- **이 분야의 말과 물건:** 응급실 트리아지 태그(분류 색이 붙은 꼬리표), 물류의 전달 전표(받는 곳이 크게 적힌 종이), 병원 구매 문서의 표. 디자인 재료를 여기서 가져온다.

## 2. 지금 화면의 문제 (캡처 기준)

| 문제 | 어디서 보이나 |
|---|---|
| 첫 화면에서 본판이 화면 중간부터 시작한다. 안내 띠·시각 띠·업종 전환·정답 대조·방향 막대가 전부 전체 폭 막대로 쌓였다 | 문의함 첫 화면 |
| **결정 버튼이 카드 맨 아래**라 스크롤해야 보인다. "넘길까요?"가 화면의 주인공이 아니다 | 결정 카드 |
| AI 근거(기관 확인·도메인·자사 기록)가 회색 상자 안 11~12px 글씨다. 제품의 핵심 가치가 가장 약하게 보인다 | 판정 근거 |
| 목록 행이 모두 같은 무게다. 판정은 묶음 제목 옆 작은 점으로만 구분되고, 급한 건(L06)도 똑같이 보인다 | 문의 목록 |
| 흔한 SaaS 카드 키트: 모든 것이 같은 둥근 흰 카드, 같은 보라 강조, `L06 · 싱가포르 · PM-50`처럼 가운뎃점으로 이은 메타 줄 | 전체 |
| 부가 정보가 연회색 소형 글씨라 영상에서 안 읽힌다 | 전체 |

## 3. 디자인 체계

### 색 (기본 5 + 판정 태그)

| 이름 | 값 | 쓰임 |
|---|---|---|
| 차트지 (Chart paper) | `#F4F6F5` | 바탕. 차가운 진료 기록지 색(크림색 아님) |
| 잉크 (Ink) | `#1A2A33` | 본문·제목 |
| 괘선 (Rule) | `#CDD5D9` | 표 선, 구분선 |
| 전표 (Slip) | `#FFFFFF` | 결정 전표 한 곳에만 쓰는 흰 면 |
| 디스패치 블루 (Dispatch) | `#1D4E7A` | 주 동작 버튼, 선택 상태. 장식에 쓰지 않는다 |

**판정 태그 색은 판정에만 쓴다**(다른 장식 색 없음): 유효 `#2E7D4F`, 애매 `#B7791F`, 국가·제휴 확인 `#2F65A8`, 무효 `#6B7780`, 사칭·위험 `#B3392F`.

### 글꼴

- **IBM Plex Sans KR** 한 가족(본문·제목 모두). 기술 문서·의료 기록 같은 단정함이 이 주제와 맞고, 한글·영문·숫자가 한 톤이다. 숫자는 `font-variant-numeric: tabular-nums`(점수·건수 정렬).
- 크기 단계(약 1.25배): 13 / 15 / 18 / 23 / 29px. **13px 미만 금지.** 굵기는 400·600 두 단계만.
- 대문자 라벨, 제목 위 작은 머리 라벨, 한 단어만 색칠한 제목은 쓰지 않는다.

### 배치 (문의함, 1440×900)

```
┌ 미리내  [의료기기|B2B SaaS]   저장 결과 재생, 메일 꺼짐   정답 대조   [판정 시작] ┐  ← 한 줄 도구 막대
├ 유효 8 │ 애매 6 │ 국가 확인 3 │ 제휴 확인 2 │ 무효 11 │ 방향 필요 6 ─────────────┤  ← 트리아지 탭(필터)
│ ▌유효  Singapore General Hospital        APAC 확인   5시간 │ ┌ 전달 전표 ─────────┐ │
│ ▌유효  서울대학교병원                    A Medical   9시간 │ ▌ 받는 곳            │ │
│ ▌애매  Mayo Clinic                       NA 권역팀   2일   │ ▌ A Medical          │ │
│  ...  (행 = 판정 태그 | 기관명 18px | 받는 곳 | 경과)       │ [승인] [딜러 변경] [전화 필요] [무효 처리] │
│                                                            │ 근거                 │ │
│                                                            │ ✓ 기관 실재, 서울    snuh.org 11-18 │
│                                                            │ ✓ 도메인 일치        Liner 검색      │
│                                                            │ ! 자사 기록 0건                      │
│                                                            │ ▸ 문의 의도(Liner 모델 인용)  ▸ 이력  ▸ 메일 미리보기 │
└────────────────────────────────────────────────────────────┴──────────────────────┘
```

- 왼쪽 정렬. 목록은 카드가 아니라 **표 행**(괘선으로 구분). 면(흰 전표)은 결정 전표 하나뿐이다.
- 사이드바의 "판정 현황" 세로 목록은 위의 트리아지 탭으로 합친다. 목록 폭이 넓어진다.
- 안내·상태 띠는 도구 막대 안의 짧은 상태 문구 하나로. 정답 대조는 버튼으로 열리는 서랍.
- 메타 정보는 가운뎃점으로 잇지 않고 **정렬된 열**로 둔다.

### 결정 전표 (이 화면에서 단 하나의 대담한 요소)

- 전표 왼쪽 끝에 판정 색 띠(트리아지 꼬리표). 맨 위에 **"받는 곳"과 딜러·팀 이름을 29px**로. 바로 아래 결정 버튼 4개. 그 아래 근거 3줄.
- 근거 줄: 상태 기호(✓ 확인, ! 주의, × 실패) + 한 줄 설명 + 줄 끝 고정 위치에 출처(도메인, 검색 시각, "Liner 검색"/"Liner 모델"). Liner가 어디에 쓰였는지 근거 줄마다 보인다.
- 부가 정보(문의 의도 인용, 90일 이력, 메일 미리보기, 회신 기록)는 접힌 줄로.

### 마케팅 화면

- 같은 체계. 요청 목록은 표 행(순위 | 요청 | 지역 | 마감 | 점수 막대).
- **캠페인 효과:** 캠페인마다 가로 막대 한 줄. 막대 길이 = 유입 리드 수, 막대 안 진한 구간 = 유효 수. "유입 6, 유효 0"이 막대 모양만으로 보인다. 효과 높음·낮음은 판정 태그 색을 다시 쓴다(유효 초록 / 위험 빨강).

### 움직임

- 판정 시작 뒤 행이 트리아지 탭으로 나뉘는 순간 한 번만(행이 자기 묶음으로 자리 잡기, 200ms). 그 밖의 진입 효과·호버 효과는 넣지 않는다. `prefers-reduced-motion`이면 끈다.

## 4. 기본값 점검 (계획을 다시 본 결과)

| 처음 떠오른 안 | 왜 흔한가 | 바꾼 것 |
|---|---|---|
| 의료 = 청록(teal) 강조색 | 헬스케어 SaaS의 기본값 | 전달·배차 문서의 **디스패치 블루**. 이 제품의 일이 "라우팅"이라서 |
| 판정 색 = 신호등 점 | 어디에나 쓰는 상태 점 | 행·전표 왼쪽의 **꼬리표 띠**(트리아지 태그 모양), 노랑 대신 호박색 |
| Pretendard | 한국 서비스의 기본 글꼴 | IBM Plex Sans KR(기록·문서 성격) |
| 모든 영역을 둥근 카드로 | SaaS 카드 키트 | 목록·표는 괘선, 흰 면은 전표 하나 |
| 큰 숫자 + 작은 라벨 통계 띠 | 대시보드 기본값 | 정답 대조는 서랍 안 표로. 첫 화면의 주인공은 리드와 전표 |

## 5. 지킬 것

- **기능·판정 로직·데이터는 바꾸지 않는다.** 버튼·라벨의 접근 이름(예: "승인", "판정 시작", "방향이 필요한 리드 N건", "LinkedIn 초안 보기")과 역할은 그대로 둔다. E2E와 녹화 스크립트가 이 이름으로 찾는다.
- 의료기기 저장 30/30, SaaS 10/10, 메일 403, 마케팅 기능, E2E 전체 통과.
- 키보드 초점 표시, 대비 4.5:1 이상, 1280px 이하에서도 깨지지 않음.

## 6. 우선순위 (시간이 모자라면 뒤에서부터 뺀다)

1. 도구 막대 한 줄 + 트리아지 탭(첫 화면에서 본판이 위로)
2. 결정 전표(받는 곳·결정 버튼 위, 근거 3줄, 부가 정보 접기)
3. 목록 표 행(판정 꼬리표, 기관명 크기, 열 정렬)
4. 색·글꼴·크기 체계 전체 적용
5. 마케팅 화면(캠페인 효과 막대 포함)
