## 배포 전 확인

- #43의 Tony 승인과 QA 결과를 확인한다. 아직 저장소가 연결되지 않은 상태에서는 #43의 커밋이 `main`에 들어갔는지 확인한 뒤 처음 연결한다. 이미 `main`에서 자동 배포되는 환경이라면 병합부터 HJ가 진행한다.
- 새 Vercel 프로젝트의 Production과 Preview에 비밀값·테스트 수신함 주소를 등록하지 않는다. 공유 환경 변수와 대시보드의 빌드 명령 재정의도 확인한다. `vercel.json`의 Next.js 설정과 `npm run build:demo`를 그대로 사용한다.
- 공개 시연의 판정·결정·재배정은 방문자 브라우저에 저장된다. 데이터 이전은 필요 없다. 첫 검증은 시크릿 창에서 한다.

## HJ 배포 절차

1. Vercel에서 **Add New → Project**를 열고 GitHub 저장소 `stynerk/onemorestep`을 가져온다. GitHub 앱이 요청하면 **Only select repositories**에서 이 저장소만 선택한다.
2. 프로젝트 루트는 저장소 루트, 프레임워크는 Next.js, 프로덕션 브랜치는 `main`을 확인하고 **Deploy**를 누른다. 이후 이 브랜치에 들어가는 변경은 자동으로 프로덕션 배포된다. [Vercel Git 연동](https://vercel.com/docs/git)
3. 빌드가 **Ready**가 되면 Vercel 프로젝트가 부여한 `.vercel.app` 프로덕션 주소와 배포 커밋을 #43에 기록한다. 아래 세 항목을 확인한 뒤 주소를 README에 반영하고 공유한다. [Vercel 기본 도메인](https://vercel.com/docs/domains/working-with-domains)

## 배포 후 확인

1. **문의함** — 공개 주소를 Chrome 1440px 시크릿 창에서 연다. ‘저장된 결과로 보는 시연 버전’ 고지와 30건을 확인한다. 판정 시작 후 그룹 수는 8/3/3/2/14이고 L06이 유효 첫 줄에 나타난다. 배정·회신 버튼을 눌러도 실제 메일이 나가지 않는 표시를 확인한다. 배포 로그와 브라우저에 환경 설정값이 노출되지 않았는지도 확인한다.
2. **결정 카드** — 소속 근거·딜러 추천을 본 뒤 L03을 V에 승인하고 기한 경과를 시뮬레이션해 U로 재배정한다. L23에서 ‘구매 문의 확인’ 회신을 먼저 기록해 비교용 리드를 준비하면 V에서 U로 1위가 바뀌는 것을 확인할 수 있다.
3. **시연 30건 정답 대조** — 저장 모드 30/30과 로컬에서 기록한 실시간 19/30이 따로 표시되는지 확인한다. L13·L05의 실시간 오판, L08의 저장 모드 한계와 다음 버전 메뉴를 확인한다.

## 되돌리기

- 직전 검증 완료 배포가 있으면 HJ가 프로젝트 **Overview → Production Deployment → Instant Rollback**에서 해당 배포를 선택하고 **Confirm Rollback**을 누른다. 재빌드 없이 즉시 프로덕션 주소가 이전 배포를 가리킨다. 수정 후 정상 배포를 승격해 자동 도메인 연결을 복구한다. [Vercel Instant Rollback](https://vercel.com/docs/instant-rollback)
- 첫 배포에 문제가 있어 검증된 이전 배포가 없으면 HJ가 프로젝트를 일시 중지하고 공유를 보류한다. 수정본 검증 후 서비스를 재개한다. 재개에는 몇 분이 걸릴 수 있다. [Vercel 프로젝트 관리](https://vercel.com/docs/projects/managing-projects)
