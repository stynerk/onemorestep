# One More Step

One More Step은 딜러망을 운영하는 제조사의 리드를 선별하고, 넘길 곳과 적합한 딜러를 추천하는 세일즈 에이전트입니다. 제1회 라이너 해커톤 .EXE-THON 출품작입니다.

## 공개 시연

[One More Step 공개 시연](https://onemorestep-wheat.vercel.app/)에서 시연 계정으로 로그인하고 **선별 시작**을 누르면 가상 리드 30건이 유효 8건, 애매 6건, 국가 확인 3건, 제휴 확인 2건, 무효 11건으로 분류됩니다. 목록과 카드에서 선별 근거와 넘길 곳을 확인할 수 있습니다.

시연 계정은 ID `medicom`, 비밀번호 `1234!`입니다. 로그인은 공개된 시연 값과 브라우저에 저장하는 입장 상태를 사용합니다. 서버 인증과 접근 제어가 없는 시연용 화면입니다.

공개 문의함은 저장된 기관 근거와 모델 응답으로 선별하고 메일 발송을 차단합니다. 결정·회신·재배정 기록은 이 브라우저에 저장되며 **시연 초기화**로 지울 수 있습니다.

**마케팅 협조 요청**에서는 본사 세일즈 요청을 점수순으로 검토하고 순위를 조정하며, Liner Search 근거가 붙은 Router 채널 초안을 확인합니다. 공개 시연은 저장된 초안을 재생합니다.

요청을 접수해 검토·완료하고, 캠페인 코드별 유입 리드의 선별 결과를 모아 다음 채널을 선택합니다.

공개 문의함에서 의료기기(Medicom)와 B2B SaaS(Flowline)를 전환할 수 있습니다. Flowline 10건의 저장 선별은 의도 규칙 6/10, Router 의도 재생 8/10, Router 도메인 근거 재생 10/10입니다. 넘길 곳은 8/10에서 10/10으로 올라 유지됐습니다. 결과를 본 뒤 같은 10건에서 비교했습니다.

## 심사위원 로컬 실시간 실행

Node.js 24에서 저장소 루트의 의존성을 설치합니다.

```powershell
npm ci
```

`.env.example`을 복사해 `.env.local`을 만듭니다. 이미 있는 로컬 환경 파일은 그대로 열어 편집합니다.

```dotenv
LINER_MODE=live
LINER_API_KEY=여기에_본인_Liner_API_키
```

```powershell
npm run dev
```

[로컬 문의함](http://127.0.0.1:3000)에서 **선별 시작**을 누르면 Liner Web Search로 기관을 조사하고 Router로 문의 의도를 판단합니다. 환경 파일을 편집한 뒤에는 서버를 다시 시작합니다. 키 없이 실행하거나 `LINER_MODE=sample`을 지정하면 저장된 근거로 시연할 수 있습니다. 메일 검증이 필요하면 [로컬 테스트 수신함 설정](docs/tech/FORWARDING_IMPLEMENTATION.md#테스트-수신함-메일-25)을 따릅니다.

**장면 6 재배정.** 저장 모드에서 L23의 제휴 회신을 **구매 문의 확인**으로 기록하고 추천 순위가 V MedSource, U Health Supply 순인지 확인합니다. L03을 V MedSource에 배정한 뒤 **기한 경과 시뮬레이션**을 누르고 **재배정 승인**을 누르면 U Health Supply에 배정됩니다. L23에서 U Health Supply가 1위로 바뀌고 V MedSource가 2위로 내려간 이유를 확인할 수 있습니다.

## Liner를 쓰는 곳

One More Step은 Liner Web Search로 리드마다 **기관명 + 국가**, **기관명 + 업종**을 검색합니다. 검색 결과로 소속 기관과 소재지, 공식 도메인을 확인합니다. 리드의 이메일과 공식 도메인을 대조해 사칭 의심도 표시합니다. 담당자는 결정 카드에서 검색 근거와 넘길 곳을 확인한 뒤 승인할 수 있습니다.

실시간 검색이 정상 완료되면 미등록 기관의 이름이 검색 결과와 일치하는지 확인하고 출처 호스트를 이메일 도메인과 대조합니다. 근거를 찾지 못한 구매 문의는 기관형 이메일을 사용한 경우 애매로 분류하고 넘길 곳을 권역 세일즈팀으로 표시합니다.

별도 공개 출처에서 기관을 확인했고 이메일이 예약·닮은꼴 도메인이면 사칭 의심으로 표시해 권역 세일즈팀이 검토하게 합니다.

문의 의도를 판단할 때는 Liner Router의 Chat Completions에 문의 메모만 보냅니다. 모델이 반환한 의도와 메모의 실제 원문 구절을 검증하고, 실패하거나 응답을 사용할 수 없으면 기존 규칙을 적용합니다. 기관·도메인·국가 및 최종 선별은 규칙으로 확인합니다. 공개 문의함에서 의료기기와 Flowline은 저장된 응답을 재생합니다. 의료기기 30건 중 26건의 결정 카드에서 Router 의도와 원문 인용을 볼 수 있고, 불명 4건에는 기존 규칙을 적용합니다. 두 업종 모두 공개 환경에서 외부 호출이 없습니다.

같은 평가 70건에서 결과를 본 뒤 Router 응답을 재생해 비교한 결과, 선별은 47/70에서 52/70, 넘길 곳은 48/67에서 52/67입니다. 5건의 선별을 바로잡았고, 제휴 확인이 정답인 1건은 애매에서 무효로 바뀌었습니다.

도메인 소유 관계가 미확인으로 남은 애매 문의는 Router가 이미 받은 검색 결과를 읽어 기관 소유 여부를 판단합니다. 출처 URL과 원문 인용을 대조하고, 기관과 도메인의 연결이 확인된 경우에만 국가·제휴·구매 확인을 계속합니다. 가상 기관·사칭 의심·무료 메일·테스트 도메인은 기존 정책을 적용합니다. 공개 Flowline에서 두 건의 도메인 판단과 인용을 저장 재생합니다. 평가 70건은 결과를 본 뒤 같은 검색 기록에서 비교했으며 선별 52/70, 넘길 곳 52/67을 유지했습니다.

애매로 분류된 리드에서는 Liner Router가 담당자에게 보여 줄 질문 문구를 만듭니다. 선택지는 질문 유형별로 고정되어 있고, 화면에서 확인한 것과 확인하지 못한 것은 앱이 선별 기록에서 채웁니다. 모델 호출이 실패하면 기본 질문 문구를 쓰고, 공개 시연은 저장된 문구를 재생합니다.

## 측정 결과

**대표 블라인드 평가 30건 (2026-11-23)**에서 선별은 **17/30 (56.7%)**, 넘길 곳은 **21/30 (70.0%)** 일치했습니다. 유효 → 무효와 거짓 유효는 각각 0건이었고, 정답이 유효인 11건 중 8건을 애매로 분류했습니다. 세트를 열기 전에 엔진 `e0c919f`을 고정하고 Liner 검색 46회, Router 의도 29회, Router 도메인 9회로 측정했습니다. [새 블라인드 평가 보고서](docs/qa/BLIND_EVALUATION_2026-11-23.md)

**대규모 보조 평가 1,000건(2026-11-25, Gemini 라벨·HJ 확인)**에서 선별은 **579/1,000 (57.9%)**, 넘길 곳은 **528/1,000 (52.8%)** 일치했습니다. 유효→무효 104건 중 100건은 Gemini가 유효로 라벨링한 가상 기관이며, 거짓 유효는 8건입니다. 측정 전에 정한 HJ 기준(가상 기관은 무효)을 적용하면 선별 **679/1,000 (67.9%)**, 넘길 곳 628/1,000, 유효→무효 4건이고, 사칭·무료 메일을 유효로 올린 건은 0건입니다. 결과를 본 뒤 HJ 결정으로 규칙 두 가지(권역 표 5개국 보완, 무료 메일·의향 약함은 자동 확인 메일)를 더해 기록된 응답만 재생하면 사람이 볼 리드는 **1,000 → 410건(−59%)**, 넘길 곳은 719/1,000이고, 자동 확인 메일 대상의 정답 일치는 197/203(97%)입니다. ## 한계

- 2차 개선 평가에서 정답이 유효인 15건 중 6건을 유효, 9건을 애매로 분류했습니다. 유효 오탐과 유효→무효는 각각 0건입니다. PR #66에서 무효로 선별한 사칭 의심 6건을 모두 애매로 분류해 권역 세일즈팀으로 돌렸습니다.
- 기관 확인이 필요한 리드의 실시간 검색에 실패하면 화면에 이유를 표시하고 담당자 확인으로 넘깁니다.
- 공개 시연은 가상 데이터와 저장된 검색 근거를 사용합니다. 여러 담당자가 공유하는 업무 기록과 실제 메일 발송은 데모에서 지원하지 않습니다.
